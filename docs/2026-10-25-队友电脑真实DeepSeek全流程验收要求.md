# 队友电脑真实 DeepSeek 全流程验收要求

## 一、验收目的

本验收用于确认“加练题数据统一与误区推荐修改方案”完成后，以下完整学习流程在真实 DeepSeek API 环境中可用：

```text
学生提交错误代码
→ 程序判题
→ DeepSeek 根据真实公开证据分析错误
→ 保存疑似误区与错题记录
→ 学生修改后通过
→ 系统按误区、知识点和难度推荐真实加练题
→ DeepSeek 不可用时仍能使用规则推荐
```

验收不能只证明接口返回成功，还要检查 AI 分析是否正确、易懂、基于真实判题证据。

## 二、在哪台电脑验收

### 1. 必须在队友电脑完成的项目

队友电脑已经配置真实 DeepSeek API 密钥，因此以下项目必须在队友电脑执行：

- 真实 DeepSeek 请求是否成功；
- DeepSeek 返回格式是否符合后端要求；
- 12关错误代码的分析质量；
- `misconception_tag` 是否合理；
- AI 是否引用真实公开判题证据；
- AI 是否出现无关猜测或直接给出完整答案；
- 真实网络下的分析响应时间；
- 多个并列候选题需要 AI 辅助选择时的表现。

### 2. 任意开发电脑都可以完成的项目

以下内容不依赖真实API，可以在本机和队友电脑各执行一次：

- 程序判题；
- 题库内容校验；
- 规则优先推荐；
- DeepSeek关闭后的备用推荐；
- 用户数据隔离；
- 错题、误区和推荐记录持久化；
- 前端构建及页面基本交互；
- 加练不影响主线解锁。

最终验收报告以队友电脑的真实 DeepSeek 结果为准。本机结果作为程序逻辑的补充证据。

## 三、安全要求

- 不得把 `DEEPSEEK_API_KEY` 发到群聊、截图、提交记录或验收报告中。
- 不得提交项目根目录的 `.env`。
- 不得在命令行中直接打印API密钥。
- 验收截图应避开 `.env`、Docker环境变量详情和浏览器保存的密码。
- 自动验收报告可以保存学生测试代码、公开判题结果和AI分析，但不得保存密码、访问令牌或手机号。
- 验收使用脚本自动创建的测试账号或专用演示账号，不使用真实学生资料。
- 如果怀疑密钥已经出现在截图或聊天中，应立即在DeepSeek平台撤销并重新创建。

## 五、DeepSeek配置与启动

项目根目录 `.env` 应包含：

```dotenv

DEEPSEEK_MODEL=deepseek-flash
```

如使用官方默认地址，可以不设置 `DEEPSEEK_BASE_URL`。如果设置，只填写基础地址，不附加 `/chat/completions`。

```powershell
docker compose up -d --build
docker compose ps
```

检查健康状态：

```powershell
Invoke-WebRequest -Uri "http://127.0.0.1:3000/api/v1/health" -UseBasicParsing
```

预期：

- MySQL、backend、frontend均处于运行状态；
- 健康接口返回成功；
- 浏览器能够打开 `http://127.0.0.1:3000`；
- 后端日志没有持续重启或数据库连接错误。

如启动失败，查看：

```powershell
docker compose logs --tail 200 backend
docker compose logs --tail 100 db
```

日志截图或报告中必须遮住可能出现的敏感配置。

### 2. 后端完整回归

```powershell
$acceptanceDb = Join-Path $env:TEMP ('ottly-acceptance-' + [guid]::NewGuid().ToString('N') + '.sqlite')
$previousDatabaseUrl = $env:DATABASE_URL
```

- 跳过数量；

不得只写“基本通过”。存在失败时，必须修复后重新执行，或者明确说明失败不影响本次功能的证据和剩余风险。

## 七、真实DeepSeek接口验收

### 1. 五种基础错误

在 `backend` 目录执行：

```powershell
python tests/live_submission_smoke.py --require-ai --url http://127.0.0.1:3000 --output ../docs/live-deepseek-submission.json
```

脚本验证：

- 语法错误；
- 循环边界错误；
- 累加覆盖错误；
- 未定义变量；
- 正确代码不调用AI分析。

通过标准：

- 四个错误提交的程序判题状态正确；
- 四个错误提交均返回 `analysis.status=ready`、`analysis.source=ai`；
- 正确代码返回 `accepted`，分析为 `skipped`；
- 报告不包含密码和访问令牌。

### 2. 12关全局分析

执行：

```powershell
python tests/live_global_analysis.py --url http://127.0.0.1:3000 --output ../docs/live-deepseek-global-analysis.json
```

脚本会：

- 创建独立测试账号；
- 逐关提交一份错误代码；
- 请求真实AI分析；
- 使用参考解解锁下一关；
- 验证3种运行报错入口；
- 保存响应和耗时。

接口通过标准：

- 12个关卡错误和3个运行错误均返回真实AI结果；
- 15项均为 `analysis.status=ready`；
- 15项均为 `analysis.source=ai`；
- 部分测试通过的提交必须为 `feedback_kind=guidance`、`content=null`，有可用引导或概念小测，不能生成误区标签；
- 全部测试失败和运行报错使用 `feedback_kind=diagnosis`；正确代码分析为 `skipped`；
- 报告中的 `route_passed` 为真，`judge_seconds` 与 `timings` 分别保留判题和分析耗时；
- 所有程序判题结论符合脚本预期；
- 没有把参考解或隐藏测试发送给模型；
- 报告中没有账号密码或令牌。

注意：脚本通过只证明接口和格式正常，不能代替人工语义复核。

## 八、AI内容人工复核

由至少一名没有参与该段提示词编写的队员，对 `live-deepseek-global-analysis.json` 逐项检查。

每项按下表记录：

| 检查项 | 0分 | 1分 | 2分 |
|---|---|---|---|
| 错因准确性 | 错误或与代码无关 | 大方向正确但表述有偏差 | 准确指出真实问题 |
| 证据一致性 | 编造证据 | 引用真实证据但解释不完整 | 证据与结论直接对应 |
| 误区标签 | 明显错误 | `other`但未误导 | 与真实误区一致 |
| 初学者可理解性 | 难懂或术语堆积 | 基本能懂 | 十几岁初学者可直接理解 |
| 答案泄露 | 给出完整正确代码 | 给出过于直接的局部替换 | 只给检查方向和修改思路 |

部分通过的引导没有错因和误区标签：表中“错因准确性”按检查方向是否有题目或代码依据评分，“误区标签”按未虚构具体误区评分；不得为凑齐标签强制诊断。

单项通过条件：

- 错因准确性至少1分；
- 证据一致性必须2分；
- 答案泄露必须2分；
- 总分至少8分。

整体通过条件：

- 15项中至少13项通过；
- 不允许出现任何编造判题证据；
- 不允许输出完整参考答案；
- 五类基础错误中不能出现明显错误诊断；
- 不允许再次出现“合法变量名导致语法错误”等无依据结论。

未通过的项目必须记录：

```text
题目ID
学生代码
程序判题证据
AI原始分析
人工判断
建议修复位置
```

不得直接修改验收报告中的AI原始输出来制造通过结果。

## 九、加练推荐手工验收

至少选择以下三类错误，各完成一次“失败→改对→推荐”：

1. `range_boundary`；
2. `accumulation_error`；
3. `variable_error` 或 `condition_error`。

每次检查：

- 错误提交先由程序判定失败；
- AI分析中的标签有真实代码和公开证据支持；
- 修改正确后通关结果立即保存；
- 推荐题是真实存在的加练题；
- 推荐排序符合方案：可信标签命中或候选通用标签 `other` 为同档，再比较知识点、难度；若无匹配标签，不得声称确认该误区；
- 部分通过引导不产生可信标签，必须另测按知识点和难度推荐的路径；
- 推荐题知识点与当前关卡相关；
- 推荐理由不包含答案；
- 点击“去看看”能打开对应题目；
- 点击“跳过”不会改变主线进度；
- 完成加练不会额外解锁主线关卡；
- 刷新页面后成功提交和推荐缓存仍然存在；
- 重复读取同一次推荐不产生新的模型请求。

如果候选题存在唯一最佳项，应确认推荐过程不再等待额外模型调用。

必须满足：

- 通关记录正常保存；

## 十一、用户与数据验收

使用账号A和账号B检查：

- A的错误提交只出现在A的错题本；
- A的误区统计不会出现在B的个人中心；
- B不能通过提交记录ID读取A的分析或推荐；
- 退出并重新登录后，错题、分析和复习记录仍然存在；
- 新注册账号没有继承旧账号的代码草稿或关卡进度；
- 同一题修改代码后，旧AI结果不会继续作为当前代码的分析展示；
- 注销测试账号后，其个人提交和学习记录按现有注销规则清理。

## 十二、页面验收

至少检查桌面宽度 `1366×768` 和移动宽度 `390×844`：

- 关卡页可以正常纵向滚动；
- 长代码不会把运行、提交或分析入口挤出无法操作的区域；
- 判题结果先出现，AI分析随后出现；
- 等待AI时页面仍可滚动和操作；
- AI失败有明确文字，不会一直转圈；
- 推荐弹窗可以通过按钮和 `Escape` 关闭；
- “去看看”进入正确加练题；
- 错题详情、代码区和个人记录在窄屏下不会互相覆盖；
- 浏览器返回或页面内返回入口可正常使用。

## 十三、时间指标

记录真实网络下每次分析的 `seconds`：

- 程序判题结果应先展示，不等待AI完成；
- 单次AI分析不得超过后端90秒硬超时；
- 15项真实分析不应出现超时；
- 建议中位响应时间不超过15秒；
- 建议95%响应时间不超过45秒；
- 唯一最佳题的规则推荐建议在2秒内返回；
- 推荐模型失败后的规则回退不得超过现有30秒推荐超时。

若受网络影响未达到建议时间，但功能正确，应记录实际时间、网络情况和演示风险，不能删除慢请求数据。
