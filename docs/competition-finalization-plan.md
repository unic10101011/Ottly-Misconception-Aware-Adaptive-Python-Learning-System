## 2. 产品定位和可证明的贡献

建议定位为“面向 Python 零基础学习者的误区感知编程陪学系统”。用一条真实学习过程串联材料：关前引导与小测 → 编写与运行 → 确定性判题 → AI 基于公开证据解释 → 错题留存与复习 → 改对后的针对性加练。

核心说明应覆盖：

1. 判题、通关和解锁由程序确定，AI 解释结果，不裁定成绩。
2. 诊断输入经过公开证据选择、输出差异整理、结构校验和内容审核；保留拒绝与服务失败的状态。
3. 全失败、运行异常与部分通过分别处理。部分通过的引导不强行生成误区结论。
4. 推荐按疑似误区、知识点和难度排序，唯一最佳题直接推荐，并列候选才由 AI 辅助选题，异常时规则回退。
5. 执行回放使用真实执行轨迹，与 AI 解释分工明确。

应如实写明模型通过 API 调用；当前难度目标固定为 1。不能把这些机制写成自研大模型、已训练的认知诊断模型、完整知识追踪或已经证实的长期学习能力提升。历史 Qwen、BRAFAR 和分类研究归入探索记录，与当前产品实测分开。

## 3. 截止前值得做的优化

### P0：影响评审复现和最终结论

- 同步队友更新后冻结一个候选版本，记录 Git SHA、依赖、镜像、模型请求名及时间。修复后新建结果记录，不混合不同版本结果。
- 更新现有 DeepSeek 验收说明：移除已经不生效的 `ANALYSIS_PROVIDER`、可配置 `DEEPSEEK_MODEL` 假设，取消“必须在队友电脑”的限制，改为实际具备授权密钥和网络的验收环境。旧 `level2` 烟测只能作补充，正式主线需独立覆盖。
- 当前入口从 CDN 获取 Bootstrap CSS。为本机评审包准备固定版本的本地 CSS 和对应许可信息；保留现有交互实现。
- 固定测试通过的 Python 依赖组合，保存 Docker 镜像标识和前端锁文件。分别验证源码构建与预构建镜像启动。
- 在一台未运行过项目的电脑或干净环境完成安装、启动、注册、运行、AI 分析、停止和重启。保留独立数据库，不触碰原学习数据。
- 讲清“本机部署”与“AI 联网调用”的区别。包内不含真实密钥；无模型服务时仍能判题，AI 功能显示真实不可用状态。
- 准备专用演示账号与演示记录，注明预置前置进度；同时保留从零注册体验路径。

### P1：提高材料说服力

- 用小规模真实模型对照试验证明结构化证据与校验审核的价值，同时报告额外耗时与 token 用量。
- 覆盖 Chrome、Edge、常用桌面分辨率与窄屏，重点检查代码输入、弹窗、滚动、错误提示和刷新恢复。
- 整理 AI 入口的等待、取消、迟到响应、重试和异常保留行为。
- 建立第三方依赖、题库参考、图标与插画来源清单。对未知来源标记待确认，不把查不到来源写成拥有授权。
- 能组织时安排 5～8 位自愿参与者完成简短试用；记录角色和经验。成人或开发者走查应按真实身份描述，不能作为儿童试点或长期学习效果证据。

### 暂不扩展

功能冻结后集中修复阻断问题。新模型训练、大规模题库扩容、教师端、公开互联网部署、长期能力建模可列为展望。

## 4. 测试方案

### 4.1 软件回归与交付验证

`921fd5d` 对应界面修改已完成前端 110 项测试、Docker 构建与本机健康检查；此前同步 `4e13999` 时完成后端回放等专项 39 项测试。更早清理阶段的 58 项及 9 个子测试仅作历史记录。这些记录不构成同一最终版本的全量报告。最终候选版本应重新运行：

- 题库校验、参考解和典型错解检查；
- 后端全量自动测试，逐项说明失败、跳过和所需外部环境；
- 前端全量测试与生产构建；
- MySQL 新库启动、旧库升级/重启、用户与数据隔离；
- 12 关主线、加练、复习、回放、历史恢复及无尽挑战核心流程；
- 旧偏好接口保持下线，账号注销清理历史偏好且不影响其他账号；
- Windows + Docker Desktop 干净环境复现，另测 Chrome/Edge 和窄屏。

保留命令、版本、日志、期望、实测、缺陷编号与修复后结果；不能只保留“通过数量”。

### 4.2 真实 AI 质量验收

建议先用 12 条开发样例排查协议、质量和耗时，记录 token 用量以估算总预算，再冻结一个未用于本轮调参的验收集。

建议正式主线验收集共 72 条：每关 4 条典型错误、1 条正确代码、1 条边界或易误判案例。具体错误应符合该关已学知识，不强求每关都有部分通过或某一种异常。整体覆盖运行报错、全失败、部分通过、正确结果、不同行输出中一部分已正确、空输入、负数、边界、重复调用，以及代码注释中的干扰指令。

每条保存：题目版本、代码、输入、真实执行结果、期望判题状态、人工确认的原因与可接受解释、允许标签、禁止声称的内容。人工标准答案不发送给 AI。正确案例验证不产生错误诊断；部分通过按引导质量评审。

运行建议：全体一轮，选取 24 条关键案例各追加两轮，共 120 次验收试次。记录所有失败和重试，不挑最好回答。一次试次可能包含多次模型调用，另记 token 和实际费用；费用在明确预算后控制。

质量复核建议由两名熟悉 Python 的人员独立进行，隐藏方案名称，记录分歧和最终依据。审核模型的“通过”不能代替人工语义评审。

| 指标 | 计算/记录方式 |
| --- | --- |
| 有效返回率 | 可展示反馈次数 / 应产生 AI 反馈的试次 |
| 语义合格率 | 人工合格反馈数 / 可展示反馈数 |
| 端到端有效反馈率 | 人工合格反馈数 / 应产生 AI 反馈的试次 |
| 证据真实性 | 引用、行号、输入与输出是否真实；是否误指已正确部分 |
| 标签表现 | 可判断案例的分类指标及弃权率；不可判断时允许保留不确定 |
| 教学质量 | 是否具体、易懂、适合初学者、未泄露完整解答 |
| 稳定性 | 同案例重复试次的正确性与主要结论一致性 |
| 性能与成本 | 判题与 AI 分别计时，报告中位数、P95、超时、重试和 token |

建议在正式运行前约定：核心流程无阻断；诊断/推荐不泄露隐藏测试或参考解；没有伪造模型成功；语义合格率目标至少 90%，同时报告端到端有效反馈率。门槛是团队建议，不是官方标准，也不是已经取得的结果。不得在看到结果后临时降低口径。

### 4.3 推荐、出题、问答与异常

- 推荐：选取约 12 条有可信疑似标签/无可信标签、唯一/并列候选、无可选题和模型异常的场景。检查选题范围、相关性、首次即通过不触发、失败改对才触发、重复读取不重复调用、规则回退和页面迟到结果。
- AI 出题：建议生成 12 道，覆盖循环、字符串、列表/函数等综合范围。保留所有候选与拒绝记录；独立人工核对题意、样例和边界，不能只用同一模型生成的参考解验证它自己的测试。
- 陪学和关前问答：建议 12 条课程相关问题，另加越界提问、上下文容量、刷新/离开恢复、回答中断和账号切换检查。
- 故障：无密钥、错误密钥、额度/限流、网络超时、非法 JSON、错误证据、错误标签、无候选和取消。可模拟难以安全触发的状态，但必须与真实调用分开报告。
- 数据边界：诊断与推荐使用允许公开的学习证据；出题/审核流程按其职责处理候选题及测试。不得把不同 AI 入口的数据约束混写。

### 4.4 对照与试用

小规模对照可先选 24 条同一验收集案例：A 为同一模型直接根据题意、代码和公开执行结果解释，B 为当前结构化证据与校验审核流程。保持案例、模型与基础生成参数一致，两组都不接触人工标准答案、隐藏测试或参考解；独立账号和受控历史避免互相污染。

报告正确性、证据错误、答案泄露、返回率、耗时和 token；多调用带来的成本差异应一起呈现。结果不支持提升时如实记录。

试用采用固定小任务，例如完成一关、修复一个错误、找到一次加练、重登恢复代码。记录任务完成率、操作阻碍和匿名反馈。短时试用只能支持可用性描述，不能推出长期学习效果。

## 5. 文档与演示材料

主技术方案建议按官方模板组织，以下为待映射的内容结构：

1. 产品背景与定位：具体学习难点、目标用户、使用场景、需求与验收标准。
2. 总体设计：React/FastAPI/MySQL/执行器/云模型架构图，标明边界、数据和部署。
3. 核心机制：证据准备、诊断、校验审核、部分通过路由、规则排序和 AI 并列选题；用伪代码、状态图和真实案例解释。
4. 功能实现：沿一条完整学习过程展示关键页面，突出输入、处理和结果。
5. 测试与优化：冻结版本、样本、对照、人工评分、性能、缺陷修复及未通过项。
6. 应用价值与差异：用功能机制和实测数据比较；无证据的市场/学习效果判断写为待验证。
7. 局限与展望：模型可能误判、有限知识点/标签、同模型审核相关性、当前难度策略、并发和安全隔离边界。
8. 附录：关键代码、第三方来源、运行指南与脱敏原始报告索引。

另准备软件使用/部署说明、核心算法说明、测试报告、演示脚本、答辩 PDF 和适用的佐证。技术方案可以概述后引用详细附录，不重复堆砌历史日志。

算法说明重点写自研的输入处理、校验、路由、排序和一致性验证；第三方大模型原理作背景介绍，区分外部服务与团队实现。

四张优先图：系统架构与信任边界；提交至反馈状态流程；失败改对至推荐流程；用户/提交/复习/生成题数据关系。

测试报告的每项结论链接到可追踪用例和原始记录。人工合成案例、真实参与者、Mock、真实 API、结构通过与语义通过分别标明。

视频建议控制在约 4 分钟：痛点与定位 25 秒；引导与做题 35 秒；真实错误、证据和 AI 分析 65 秒；改对、推荐与复习 50 秒；执行回放/无尽挑战 35 秒；测试结果与局限 30 秒。字幕标注真实等待时长及剪辑；历史响应回放应明确标识。

## 7. Docker 运行包建议

运行包包含源码、锁定依赖、Compose、启动/停止脚本、不含密钥的配置示例、安装与 AI 联网说明、专用演示数据说明及校验信息。另提供预构建镜像导出包，避免评审现场依赖镜像站下载；按 x86_64/实际测试平台注明支持范围。

包中排除真实 `.env`、数据库卷、浏览器令牌、真实用户资料、研究快照、缓存和开发依赖目录。用于演示的数据与真实试用结果分别存放。页面能够判题但 AI 不可用时应如实说明；录制的视频与脱敏模型结果可提供效果证据，不能伪装成当前在线回答。

最终由另一人从拿到运行包开始独立走一遍，按方案中的相同操作复现，确认代码、文档、视频、模型配置和测试报告都对应同一发布版本。
