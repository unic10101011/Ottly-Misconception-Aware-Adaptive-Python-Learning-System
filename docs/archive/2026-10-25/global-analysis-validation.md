# 全局错因分析验收

2026-10-22，本机 Docker 前后端、MySQL 与 Ollama 的真实 HTTP 验收，模型为 `qwen2.5-coder:7b-instruct-q4_K_M`。

## 接入范围

- 12 个当前关卡共用诊断服务，不再按第一、二关选择生成提示词。
- 运行报错使用本次实际输入、异常和同一次执行结果自动分析，不重跑代码、不保存为正式提交。
- 提交失败保留先判题、后分析的流程；成功运行和通过全部测试时不调用分析模型。
- 关卡编辑器及错题复习编辑器均展示运行分析；自由运行不要求题目 ID。
- 自动化测试还注册了不在关卡列表内的题库 ID，验证相同接口可复用。未来抽题功能本身未实现。
- 只向模型提供公开执行证据，不提供参考解和隐藏测试数据；所有题目诊断均不混入历史错因。

真实响应保存在 `live-global-analysis.json`（历史本机报告，仓库未收录）。该次 15 次分析均为 `ready`、`source=ai`。这只证明调用、结构及来源检查通过，**不代表全部分析正确**。

## 复现

启动项目后，在项目目录执行 `python backend/tests/live_global_analysis.py`。脚本创建独立测试账号，逐关提交错误样例，再用参考解解锁下一关；参考解只用于解锁，不发给诊断模型。报告不保存账号密码或令牌。测试用例的 `expected_cause` 只用于人工复核，也不发给诊断模型。

已保存的旧分析不会自动重算，体验新流程需刷新页面并重新运行或提交。
