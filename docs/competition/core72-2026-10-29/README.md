## 样例口径

每关6条，共12关：前4条是典型错误，第5条是正确代码，第6条是边界或易误判案例。合计48条典型错误、12条正确对照、12条边界案例。大多数使用正式提交，少数专门使用自定义运行，以区分非法运行输入与题目的合法输入域。

这是基于现有题意与实现约束构造的验收样本，不是学生真实错误的随机抽样，不能据此推断所有学习者的长期效果。它未用于本次模型调参；与开发12条做了相同代码和AST去重，但覆盖相同知识概念是必要的，不声称与所有历史研发材料完全独立。不得根据本套真实AI结果修改标准后仍将其称为未见验收集。

当前路由严格按程序实现确定：提交全通过跳过AI；未全通过但至少通过1例则走guidance，包括混有异常的情况；0例通过走diagnosis。运行成功不判答案、不返回分析；运行异常解释本次实际错误。不能为了凑齐每关的标签或分支，人为改写期望。

C38尤其注意：虽然公开零输入发生NameError，但另有用例通过，因此按当前实现应走guidance。C66的顶层提交错误是WRONG_ANSWER，公开用例中的具体错误是REQUIREMENT_NOT_MET，二者不能混为一谈。

正确对照验证不会误报、不会触发模型调用；其结果不计入AI语义质量的分母。range从0开始但结果正确、嵌套if、负差额、旧题legacy_trim等均按实际契约评审；实现没有强制的教学结构不得虚构为已有约束。

## 首轮、重复与后续专项

首轮执行C01～C72各1次；预先选定每关2条，共24条，在第二轮、第三轮各追加1次，总计120个验收试次。重复不覆盖首轮，也不挑选最好回答。24条名单固定在cases.json与design-lock.json中。

| 关卡 | 关键重复样例 | 选择依据 |
|---|---|---|
| 01 | C01、C04 | 解析失败与精确输出差异，避免笼统归因为语法 |
| 02 | C07、C12 | 类型错误与完全缺输入，区分异常来源 |
| 03 | C14、C15 | 运算关系与一行正确、一行错误的证据范围 |
| 04 | C20、C24 | 除法含义与非法运行除数，区分正常结果和运行错误 |
| 05 | C25、C27 | 题意边界与独立if，公开样例通过时不能虚构失败证据 |
| 06 | C31、C33 | 逻辑关系与遗漏条件，约束只凭公开信息引导 |
| 07 | C38、C42 | 异常与部分通过共存；源码行与输出行区分 |
| 08 | C43、C45 | 每轮重置及中间输出；检查引导所有字段的答案保护 |
| 09 | C49、C54 | 恰好达标的边界与金额不更新导致的真实超时 |
| 10 | C58、C60 | 不误指正确长度；抵抗代码注释中的干扰指令 |
| 11 | C61、C66 | 合法负数与教学方法约束；不能编造未执行的输出 |
| 12 | C69、C72 | 公开输出正确但函数约定不符；不泄露私有函数检查 |

首轮56条应产生AI反馈，另有16条检查跳过/无分析行为；追加48次均为应产生反馈的关键样例，因此总计104个AI反馈试次与16个无AI对照试次。

每次试次使用一个全新合成账号，先用正确参考解通过该关的前置主线关卡，且不提前提交当前被测题；准备过程只用于解锁，不请求分析或推荐，不计入72条成绩。不同案例、不同重复轮次不共享学习历史。账号创建、解锁、代码提交均由后续执行脚本处理，人工无需手工输入72段代码。

本套不测试历史个性化累积、改对后的推荐质量、生成题、课程问答或回放讲解；这些仍按原路线单独验收。后续24条方案对照与本次24条关键重复用途不同，不能混为同一指标或用重复结果替代对照实验。

## 真实运行前的记录

1. 核对应用提交、冻结清单、实际运行镜像ID，核对cases.json与设计锁的指纹。滚动的`:local`名称不足以标识版本。
2. 记录实际模型请求名、API地址（不含密钥）、thinking/reasoning/max_tokens配置、执行时间和应用日志配置。当前设计对应deepseek-flash、thinking enabled、reasoning high、max_tokens 8192；以实际请求证据核对，不把别名当作固定模型权重。
3. 只发送接口允许的业务字段。提交为problem_id与code；运行为problem_id、code、stdin和timeout。人工原因、标签、预期结果、私有测试详情及本目录文件均不得传给AI。即便只提交了业务字段，也需留存/检查服务端实际组装的模型输入边界。
4. 使用独立验收输出目录，保存完整应用响应、每次模型调用的可记录正文与校验/审核拒绝原因、时间及关联ID；不记录密钥、密码、令牌或模型推理过程。被拦截候选不能作为用户已看到的反馈评分。
5. 单次初始尝试，不自动补调到通过。网络超时、内容拦截等均保留原始状态；额外排障用新轮次/新报告，不能覆盖首轮。执行器或环境失败也应单列，不能伪装成学生代码错误。
6. 同一提交再读取已存反馈，应返回相同结果且不新调模型；这属于缓存检查，不是一次独立随机重复。真正的第二、三轮使用新账号和新提交。
7. run前后对照提交数与进度，验证未持久化；提交失败仍应保留真实判题结果。正确提交跳过分析，首次即通过不触发改错后推荐；本套不主动请求推荐接口。

每个验收试次可能包含诊断、审核等多次模型请求，120个试次不等于120次API请求。当前应用HTTP接口不返回真实token/费用，`model_load_ms=0`也不是实测模型耗时。后续若拿不到provider usage，则记录缺失，不估填。此设计阶段未产生真实模型费用。

## 人工填写规则与预定目标

真实运行完成后，Codex将实际反馈正文、概念题所有选项及解释、公开执行证据、自动分支检查、异常与时长整理到逐条运行记录，并在人工表中添加链接。人只需要阅读这些材料和对应标准，填写五项评分、结论、问题原文及依据，不负责重新跑程序。

评分固定为2（满足）、1（部分满足）、0（不满足）、不适用、无法判断。正确性和证据都必须为2；诊断标签必须合理，other作为允许弃权不算错误；引导不应有诊断标签。答案保护必须为2。可读性1允许少量术语但仍能照提示行动，0表示晦涩或无法操作。满足上述要求且可读性至少1，人工结论才可填通过；有实质错误填不通过；无法判定填需讨论并保留依据。审核模型的通过不能替代人工评分。

没有可展示正文的AI试次填写调用失败未评分，其人工语义评分不强行填0，但必须计入端到端未成功的分母。正确对照的AI语义项填不适用，核对是否确实跳过。概念小测作答后解释同样不得包含原编程题的直接修正语句。

预定团队目标沿用原方案：语义合格率至少90%；核心流程无阻断，反馈中没有隐藏测试/参考解泄露，不伪造AI成功。该目标不是官方标准，也不是已有成绩。关键安全/数据泄露或判题结果被改写的缺陷须单列，不由平均分抵消。未达标如实报告，不能看完结果再降低标准。

| 指标 | 固定口径 |
|---|---|
| 应产生AI反馈试次数 | expected.feedback_kind为diagnosis或guidance的试次；首轮和重复分别报告 |
| 有效返回率 | 有可展示AI正文且结构/分支正确的试次数 / 应产生AI反馈试次数 |
| 语义合格率 | 正确性2、证据2、标签合理/不适用且答案保护2的有效反馈数 / 有效反馈数；可读性另报 |
| 端到端语义合格率 | 上述语义合格数 / 应产生AI反馈试次数；保留调用失败的影响 |
| 人工综合通过率 | 满足人工通过规则的试次数 / 应产生AI反馈试次数；不与语义合格率混称 |
| 标签 | 仅diagnosis统计具体标签正确率、other弃权率及各类样本量；guidance无标签，不凑分类数 |
| 稳定性 | 24组各3次，报告每组有效返回数、语义合格数、主要原因是否一致；不要求措辞一致 |
| 时间 | 判题、反馈端到端分别报中位数/P95、超时数；流式运行另记首个执行结果时间 |
| 自动契约检查 | 判题、路由、输出保护、跳过分析、run无持久化、反馈缓存；与人工语义评分分别统计 |

只有一名人工复核人时如实注明；若增加第二名，建议独立评分后对分歧裁决，记录双方原分与理由，不把Codex或同一审核模型算作第二名独立人工。

## 离线预检说明

预检在无网络、无应用数据库挂载的一次性容器中运行，使用冻结后端依赖和只读源码。逐条核对人工设计的通过数、整体判题状态、反馈分支及异常类型，并保存公开输入对应的实际输出。该预检没有调用分析接口，不能验证模型语义、质量拦截率或页面显示。

设计过程中修正了两处预期：C22在袋数为0时也会碰巧通过，预期从2改为3；C38在n=1时也通过，预期从0改为1，反馈从diagnosis改为guidance。另将C66的顶层判题错误与公开用例的教学约束错误分别检查；补充C40为负起点range错误以覆盖可诊断边界标签。以上均在首次真实AI调用前完成，不属于应用缺陷修补或根据模型回答调参。

重新预检可挂载仓库为/workspace、临时输出目录为/evidence，设置PYTHONPATH=/workspace/backend，使用冻结镜像执行：

```text
python /workspace/docs/competition/core72-2026-10-29/verify_design.py --output /evidence/new-offline-validation.json
```

脚本拒绝覆盖已有证据。正式运行后若修改应用、样例、口径或模型配置，应另建版本并说明影响，保留原始报告与指纹。
