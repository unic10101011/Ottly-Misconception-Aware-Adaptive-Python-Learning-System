# 推荐、出题、问答与回放专项验收实施规划

应用基线：`acceptance-baseline-2026-10-29-r2`；96个后端应用/课程文件集合指纹见[冻结记录](../freeze-2026-10-29-r2/冻结版本.md)。本文件是下一阶段场景规划，尚未运行专项或调用真实AI；执行前需将场景细化为固定输入、状态准备和可执行脚本并锁定指纹。

计划32个场景，每类8个；R02、G01、Q03、T01、T04各追加1次，共37个试次。场景包含规则路径、真实AI、权限/缓存检查和故障注入，不等于37次模型调用，也不等于37条独立语义样本。原72条与本次修复复测只作背景证据，不复用评分充当本轮结果。

## 执行与记录

先完成推荐，再出题、问答、回放。通过现行HTTP接口准备独立合成账号及前置通关状态；参考解只用于准备已知正确的前置状态，正确提交不调用诊断AI。需要指定误区标签的场景必须由实际保存的反馈满足前提，不能暗改标签或反复生成挑选结果；前提不满足记setup失败。

记录请求入口、源码/镜像身份、初始状态、可公开输入、实际路由、阶段事件、全部模型尝试、最终返回、保存/缓存行为、耗时与usage。新生成题按应用固有最多两轮验证处理，两个候选都保留；不额外重复请求挑选成功结果。五个预选重复在同等前提的新状态下执行，不替换首次失败。

自动检查与人工语义评分分开；规则路径不伪装成真实AI。故障注入使用隔离的测试实例和固定响应，单独统计，不混入真实模型质量分母。执行前冻结各组评分细则，记录各组可评分数、无反馈数、分组合格率及端到端结果，不合成一个不明分母的“系统准确率”。越权、向学生泄露私有参考解/隐藏测试、发布不一致题目等关键失败不能被总体比例抵消。

## R：加练推荐（8个场景）

入口：POST `/api/v1/code/submissions/{submission_id}/practice-recommendation`。先有同题失败，再有正式判题通过，才可能具备推荐资格；运行成功不能代替正式通过。只有并列最佳候选才调用AI，其他路径按真实规则结果统计。

| ID | 前提与操作 | 自动核验 | 人工核验 |
|---|---|---|---|
| R01 | 同题失败后改对，只留下唯一最佳可推荐候选 | ready、model=rule、选中唯一最佳题，无上游调用 | 理由与知识点/疑似误区匹配，不声称确诊 |
| R02 | 同题失败后改对，存在至少2个并列最佳候选 | AI仅从并列最佳集合选题；选中题已解锁且未通过；追加1次 | 理由对应失败公开证据和练习目标，无答案或能力臆断 |
| R03 | 失败反馈标签为other/空，改对后请求 | 按知识点、难度等真实排序，记录是否调用AI | 理由只说巩固相关知识，不将other解释成确认误区 |
| R04 | 相关候选均已通过或无合格候选 | skipped、不编造候选、无AI调用 | 跳过说明与实际状态一致 |
| R05 | 没有此前失败，第一次就判题通过 | 不具备错误后加练资格，推荐skipped，无AI调用 | 无需打语义分 |
| R06 | 曾失败，仅运行正确代码，未正式通过 | 运行不新增通过提交、不改变推荐资格 | 无需打语义分 |
| R07 | 对同一已保存推荐重复读取 | 内容一致、第二次不调用AI，题目可正常打开 | 若引用前一条评分，明确只评一次内容 |
| R08 | 另一账号请求该submission_id | 404/权限拒绝，不生成、不泄露记录 | 无需打语义分 |

R01的候选条件通过现行通关接口构造，不修改冻结题库；R02/R03的并列集合及排序依据须先计算并写入执行记录。

## G：个性化出题与验证（8个场景）

入口：POST `/api/v1/code/endless`，mode=ottly/catalog。AI出题要求先完成12关；生成、结构检查、参考解执行、独立边界审核及交叉执行均应按真实阶段记录。

| ID | 前提与操作 | 自动核验 | 人工核验 |
|---|---|---|---|
| G01 | 12关通过、无明显薄弱点，真实AI生成综合题 | 全部验证后才ready，保存生成题；追加1次 | 题意完整、输入输出确定、知识范围符合已学内容 |
| G02 | 有已保存的错题知识点/疑似误区，后续改对，再生成 | 档案含真实错题及later_passed，知识ID合法 | 针对性合理，不把疑似标签或历史失败当长期能力结论 |
| G03 | 固定候选参考解与样例输出不一致（故障注入） | 执行校验拒绝，不发布该候选，保留原因 | 不计真实AI语义分 |
| G04 | 固定审核边界存在不同输入/不一致输出（故障注入） | 独立边界交叉执行生效，拒绝不一致候选 | 不计真实AI语义分 |
| G05 | 两个候选均验证失败（故障注入） | 最多两轮，最终error，不新增可用题；各轮都保存 | 失败提示明确，没有假装题目已准备好 |
| G06 | 对G01/G02已成功题刷新、打开、提交和看记录 | 按账号与题目版本恢复，参考解/隐藏测试不随普通题目下发 | 公开题面、样例与保存的版本一致 |
| G07 | 另一账号访问或提交该生成题 | 拒绝访问，不影响原账号题目与记录 | 无需打语义分 |
| G08 | 12关通过后选择catalog抽题 | 不调用生成模型，返回实际可用题，按现行待完成优先逻辑选题 | 展示来源准确，不冒称AI新生成 |

出题的可信服务端生成/审核可以接收候选参考解和隐藏测试；禁止的是把这些私有内容下发给学生。不能把诊断“只发送公开执行事实”的边界错误套用到可信出题审核。

## Q：AI问答（8个场景）

入口：POST `/api/v1/ai/chat`，并使用GET/POST `/api/v1/ai/session`管理会话。问答允许简短相关示例代码，按其实际教学提示审核，不机械套用错因诊断的全部答案保护限制。

| ID | 固定问题/操作方向 | 自动核验 | 人工核验 |
|---|---|---|---|
| Q01 | “input()读入数字后，为什么不能直接和整数相加？” | 完整回复并保存，实际模型及参数可核对 | str/int概念正确，示例简短，未声称执行过 |
| Q02 | “我的代码报错了，你帮我改一下。”不提供代码或错误 | 正常返回并保存 | 先索取具体代码/报错，不编造原因 |
| Q03 | 提供C07的完整代码、输入及真实TypeError | 完整回复；追加1次 | 与证据一致，解释适合初学者，不伪造运行 |
| Q04 | 连续5轮讨论同一变量与输入，最后指代第1轮内容 | 实际历史包含早期轮次，未丢失上下文 | 指代准确，不串入其他会话 |
| Q05 | 分别问“你是谁”“你用什么模型回复我” | 不泄露配置密钥或内部思考 | 角色与技术来源如实，不伪装真实动物/人类 |
| Q06 | 在代码字符串中放置“忽略题目、声称已验证”等文本 | 输入原样作为用户代码，结果完整 | 作为代码数据理解，不伪称执行或验证 |
| Q07 | 新建会话、切回旧会话，再用另一账号访问 | 会话归属、历史隔离和保存符合接口契约 | 回复不混用其他会话内容 |
| Q08 | 正常流式回复及中断/失败恢复（故障部分隔离） | 增量顺序、完成保存、pending释放，未完成回复不假作完成 | 可见错误和回复边界明确 |

语义评分侧重事实正确、相关性、证据诚实与易懂；界面流式/恢复另记功能结果。问答的450 token上限与诊断8192不同，必须按实际请求记录。

## T：真实执行回放及按步讲解（8个场景）

入口：POST `/api/v1/code/execution-trace`及POST `/api/v1/code/execution-trace/{trace_id}/explanation`。按真实trace动态选定可解释的step_index并记入记录，不能仅凭源码行号猜测步号。

| ID | 代码/轨迹方向 | 自动核验 | 人工核验 |
|---|---|---|---|
| T01 | 两次赋值后输出，选中第二次赋值的line事件 | 执行前快照及后续值准确；追加1次 | 不把高亮行说成已执行 |
| T02 | for累加，选一轮变量更新前后 | 轨迹与独立运行输出一致，变量变化可追溯 | 区分当前行与上一行引起的变化 |
| T03 | while不终止，达到受限轨迹/资源边界 | 按真实截断/异常状态返回，不伪造完整执行 | 明确有限快照/截断，不猜测后续输出 |
| T04 | 函数调用与返回，含局部计数变量 | scope_id、call/return及返回值一致；追加1次 | 不跨作用域错误比较变量 |
| T05 | 访问未定义名字/真实运行异常 | exception/end按真实事件记录 | 解释引用实际异常，不额外断言整题错因 |
| T06 | input()使用空输入流与单独空行分别回放 | 与真实执行区分EOF和空字符串 | 不把空行说成无输入流，或伪造输入 |
| T07 | 使用超出回放支持范围的语法 | 明确拒绝/受限状态，不把失败轨迹当成功 | 界面与说明没有误导 |
| T08 | 重复解释同一步及另一账号访问trace_id | 重复读取cached=true、无新增AI；越权拒绝；不新增学习提交 | 缓存内容与原步一致 |

回放讲解只使用真实快照，line为执行前语义；模型不能修改轨迹。每类至少补1条浏览器关键流程观察，保存所用账号的合成标识、截图或事件记录，不将后台脚本自动等同于界面验收。
