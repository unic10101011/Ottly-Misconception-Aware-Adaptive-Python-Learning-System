# Ottly 本机演示版

## 启动

在 Windows 上先启动 Docker Desktop，然后双击 start-demo.bat。首次启动会下载并构建镜像，脚本会在本目录生成仅供本机使用的 .env，其中包含随机数据库密码和 JWT 密钥。页面地址是 http://127.0.0.1:3000。

拉取更新后再次运行 start-demo.bat，脚本会重建前后端以应用新代码。启动脚本支持查找 Docker 的用户安装目录和系统安装目录，并输出完整构建步骤。构建中的 `#24` 等编号只是步骤编号，应结合后面的步骤名称判断进度；如果长期停在执行命令阶段，可先在 Docker Desktop 中重启引擎后重试。在 PowerShell 中运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-demo.ps1 -NoBrowser` 可启动并检查服务而不自动打开浏览器。

若 Docker 提示 `WSL is unresponsive`，退出 Docker Desktop 后执行 `wsl --shutdown`，再启动 Docker Desktop。若关闭 WSL 的命令也一直无响应，请保存工作并使用 Windows 的“重启”，之后等待 Docker 引擎就绪再运行启动脚本。不要使用“恢复出厂设置”处理此问题，以免清除数据库卷。

双击 stop-demo.bat 可停止服务。数据库保存在 Docker 命名卷中，停止服务不会删除账号和聊天记录。不要把 .env 上传到 GitHub。

可在本目录运行 docker compose ps 查看服务，运行 docker compose logs backend 查看后端错误。

已有数据库升级本轮契约前，需要备份并运行显式迁移；应用不会用 create_all 自动补旧表列。检查命令为 backend 目录的 `python migrate_submissions.py`。SQLite 使用 `--apply` 自动备份后加列；MySQL 先完成外部备份，再使用 `--apply --backup-confirmed`。完整操作和回退步骤见 [契约 v1 实施与迁移](docs/05-契约v1实施与迁移.md)。

## 注册和登录

注册需要用户名、密码和手机号。登录后页面会验证令牌；聊天记录、职业选择记录和设置接口按当前登录账号隔离。当前未接入短信验证码，所以密码重置入口和接口已停用。请保存演示账号密码。

新注册密码需为 12–128 个字符，后端拒绝部分常见弱密码、单一重复字符以及与用户名或手机号相同的密码；旧账号登录保持兼容。密码使用 Argon2 哈希保存，注册和登录响应不返回密码。此校验不是完整的泄露密码库查询：浏览器密码管理器若提示凭据出现在已知泄露记录中，应使用独立的新密码，不能通过关闭浏览器提示处理。注册密码框使用 `new-password`，登录使用 `current-password`。

关卡编辑器会在每次编辑时把代码和运行输入保存为当前浏览器的本机草稿，按已验证的账号 ID 和题目 ID（包含题目版本）区分。返回关卡、刷新以及退出后重新登录均可恢复，主动清空代码也会保存为空草稿。两个退出登录入口都只清理登录令牌。清除网站数据、更换浏览器或设备不会同步草稿；浏览器拒绝写入或空间不足时，编辑器会提示复制备份。该功能不改变正式提交、判题或通关记录。

## AI 模型

AI 对话按登录账号保留当前会话：切换页面或刷新后会恢复，回复生成中离开页面后也可继续查看。后端服务重启（包括项目整体重启）后自动开启新对话，旧记录仍在“历史记录”和会话下拉列表中；也可以主动点击“新对话”。当前会话指针保留在单进程后端内存中，不依赖浏览器缓存，不修改历史表结构。

对话不再静默截断为最近四轮。当前使用 8192 token 的模型上下文配置，按 UTF-8 字节数保守估算输入容量并预留回复与模板空间，最多保留 20 轮；先达到容量预算或轮数保护时会提示新建对话，并禁止继续向旧上下文发送。该预算是保守保护，不是精确的模型 tokenizer 计数。新建后尚未发送的问题会保留在输入框中。

本机演示使用 Ollama 运行 `qwen2.5-coder:7b-instruct-q4_K_M`（7B，Q4_K_M 量化）。先在 Windows 安装 Ollama，重新打开 PowerShell，再运行 `ollama pull qwen2.5-coder:7b-instruct-q4_K_M`。模型权重保存在本机，不包含在仓库或 Docker 镜像中。

运行 `ollama list` 检查已下载的模型，配置中的模型名称必须与列表中的完整名称一致。本仓库 `ollama/Modelfile` 保留的是旧 3B 手动导入模板，当前 7B 模型直接使用 Ollama 下载的版本，无需执行该模板。

.env 中的 LOCAL_LLM_URL 默认设为 http://host.docker.internal:11434/api/chat，OLLAMA_MODEL 默认设为 `qwen2.5-coder:7b-instruct-q4_K_M`。AI 聊天继续使用这套本地配置，Docker 后端通过 host.docker.internal 访问 Windows 上的 Ollama。若 Ollama 未运行，AI 聊天会显示调用失败；其他页面仍可使用。

编程助教可独立使用 DeepSeek Flash 云端模型。在项目根目录已有的 `.env` 末尾添加以下配置，将占位文字替换成 [DeepSeek 平台](https://platform.deepseek.com/api_keys) 创建的密钥，并确保账户有可用额度：

```dotenv
ANALYSIS_PROVIDER=deepseek
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_API_KEY=替换为你自己的API密钥
```

保存后运行 `docker compose up -d --build --no-deps backend`。默认 API 地址为 `https://api.deepseek.com`，可通过 `DEEPSEEK_BASE_URL` 设置基础地址（不含 `/chat/completions`）。密钥只由后端读取，`.env` 已被 Git 忽略，不要把密钥写入前端、聊天、截图或仓库。已有的 LOCAL_LLM_URL 和 OLLAMA_MODEL 不需要更改。

切换后，所有编辑器的错因诊断及诊断审核都使用 `deepseek-flash` 的思考模式和 JSON 输出；同一套证据、格式和内容校验继续生效。只有最终诊断会展示、保存，模型的 reasoning_content 不会作为错因展示或写入学习记录。相关代码、题目描述和公开执行结果会发送给 DeepSeek，按 API 用量计费；不发送隐藏测试内容、聊天记录或账号身份。加练推荐继续根据通过校验的分析知识点匹配现有题库。

DeepSeek 密钥缺失、无效、余额不足、限流、超时或诊断不合格时，会说明配置或调用问题并保留真实判题结果，不自动改用本地模型或固定诊断冒充云端结果。旧提交中已经保存的分析不会自动重算，需要重新运行或提交。若要手动恢复本地编程助教，将 `ANALYSIS_PROVIDER` 改为 `ollama` 后更新后端；未设置该项时也默认使用 Ollama。模型接口说明见 [DeepSeek 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

全部 12 关的关前引导提问页支持输入问题并点击“发送问题”，由 DeepSeek-V4.1-Flash（`deepseek-flash`，非思考模式）结合当前关卡讲解回答，可连续追问，在本次引导的“历史对话”中查看问答。该入口始终使用 DeepSeek，复用后端 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_BASE_URL`，不受 `ANALYSIS_PROVIDER` 控制。点击“我明白了，继续”可以直接跳过提问，等待回答时也可继续；仍需答对后续知识小测才记录引导完成。调用失败时保留输入供重试，不影响继续。自由问答不创建判题或通关记录，退出或刷新后不保存；当前关卡公开讲解和本次引导最近的自由问答会随问题发送给 DeepSeek。

### 体验编辑页 AI 错因分析

登录后在任意已解锁关卡输入 `print(message)`，点击“运行”或“提交判题”。运行报错后自动分析本次输入；提交失败时先显示判题结果，再自动生成分析。点击编辑器旁的“查看错因分析”查看原因、真实执行证据和相关知识点。“我的错题”复习编辑器也显示运行报错分析。运行成功不判断答案是否符合题目，正式判题仍使用“提交判题”。

错因由真实模型根据当前代码、实际输入、公开输出或异常生成。所有题目共用同一诊断服务，分析不混入历史提交；未来题库题目只需注册为标准题目并复用运行、提交接口。抽题功能本身尚未实现。

关卡编辑器运行出错时先显示真实执行结果，再等待 AI 分析，模型分析期限为 90 秒；等待期间“提交判题”旁显示“Ottly正在分析错因”。不会再次执行代码，也不会把运行写入错题本或通关记录。模型不可用或分析未通过检查时保留真实执行结果。Ollama 模式可提供明确标记的固定基础说明，DeepSeek 模式保留调用失败的具体原因。模型仍可能误判，`ready` 不代表语义必然正确。

所有错因分析入口（关卡、错题重练及历史记录）仅展示错因、分析依据和相关知识点，直接展开分析详情；不再展示 AI 学习提示、三级提示及查看提示按钮。后端历史数据及提示接口保留兼容。

错因消息入口和展开窗口固定在关卡视图右上角，页面滚动后仍可查看；每条新消息到达时入口强调两秒，随后恢复常态。通关后“前往下一关”位于“提交判题”右侧，最后一关不显示下一关按钮。

分析向模型提供字符差异、逐行是否匹配及本次诊断范围，避免把正确输出也当成错误。全关卡及运行错误的真实接口记录见 [全局分析验收](docs/live-global-analysis.json)，可用 `python backend/tests/live_global_analysis.py` 重新执行；自动检查来源与接口，语义仍须逐项人工核对。旧降级结果不会自动重算，请刷新页面并重新提交。通关复盘、参考解和下一关入口位于右侧编辑器的判题结果下方。

本轮人工复核仍发现边界条件、最大值更新等语义误判，同模型审核未全部拦截。逐项问题和可确认的接入范围见 [全局分析验收说明](docs/global-analysis-validation.md)。

### 错题改对后的加练推荐

12 个主关卡中，同一学生在一次正式判题失败后，修改代码并通过，才会触发加练推荐；首次提交就通过、连续重复提交正确答案、仅运行报错，以及通过加练题都不会触发。触发判断来自已保存的提交记录，切换页面或刷新不会丢失失败历史。

通关结果先保存并显示。45 道加练题来自经过校验的固定题库，36 道集中式题目与 9 道独立题目在运行时统一提供难度、目标误区标签和来源链接。系统先筛选同知识点、已发布、已解锁且尚未通过的题，再按已审核 AI 分析的疑似误区标签、知识点和难度排序；第一版目标难度固定为 1。唯一最佳题直接推荐，只有多道题前三项排名相同时才让编程助教辅助选择。模型不可用、超时或返回非法内容时使用规则第一题，不影响通关记录。

没有可信标签或标签为 `other` 时，只按知识点、难度和稳定题目 ID 推荐，不认定具体误区。模型只看到并列候选和公开失败证据，不接收来源链接、隐藏测试或参考解，也不生成新题。推荐结果按本次成功提交缓存，重复读取不会再次调用模型；历史推荐继续原样读取，不需要数据库表结构迁移。来源链接用于追踪教学参考，不表示直接改编或复制上游题目。

推荐成功后弹出使用 Ottly 图标的卡片，展示题目名称和简短推荐理由。“去看看”直接进入该题的题目与编辑器，“跳过”或 Escape 关闭弹窗并留在当前关卡。选题期间可继续操作或前往下一关；离开页面、开始新运行或编辑代码后，过期的推荐不会突然弹出。没有合适题目时保留正常通关提示；加练失败、通过或跳过均不改变主线解锁状态。

## 当前边界

本演示只监听本机 127.0.0.1:3000。运行与提交接口要求登录，复用原沙箱，在短生命周期子进程中执行；提交限 6000 字符、每用例 3 秒、输出上限 8000 字符。超时会终止执行进程，并明确标记输出未采集。此举解决卡死与输出串扰，并不构成针对恶意代码的操作系统安全隔离；目前只供团队本机演示。

12 关已统一为第 2 关的完整学习页面：情境、知识讲解、任务、样例、代码编辑、运行输入输出、错因分析、判题与学习记录，以及通关后查看参考解。第 1 关无需输入；第 2～12 关使用受控输入及公开、隐藏多测试。失败时使用所配置的编程助教分析；Ollama 模式保留有来源标识的基础分析兜底，DeepSeek 模式明确显示调用或内容校验失败。逐关通过后解锁下一关，第 12 关通关后显示课程完成。第 11 关检查列表、for 及常见最大值和排序函数限制，第 12 关额外检查函数重复调用、整数返回值与输入列表不变。旧 `level2` 循环题保留供历史复习，不计为新版第 2 关通关。本轮新增内容与验收见 [12 关接入与验收](docs/07-12关接入与验收.md)。

设置页面的护眼模式和语言暂存在当前浏览器，昵称按钮尚未保存到账号；逐步回放与 AI 出题尚未接入。.env、Docker 命名卷和 AI 模型服务不在 Git 仓库内。第 2 关的内容位置和验收步骤见 [第 2 关接入与验收](docs/04-第2关接入与验收.md)。

学习接口采用 schema_version=1.0.0，题库校验知识点、难度、题目版本和前置引用；解锁由 prerequisite_problem_ids 决定。提交保存元数据快照，提供规范英文错误码和 failed_tests；历史记录缺失的元数据不推断。分析知识点编号由后端精确映射。队友对接见 [实施契约](docs/05-契约v1实施与迁移.md) 与 [响应样例](docs/contract-v1-examples.json)。

旧版接口、文件职责、三种错误示例、错误处理和测试步骤见 [提交判题与提示接口说明](docs/submission-flow.md)。真实模型验收数据见 [live-submission.json](docs/live-submission.json)。

## 开发检查

在 backend 目录使用 Python 3.11 虚拟环境安装 requirements.txt 与 pytest，先运行 `python validate_catalog.py --check-solutions`，再运行 `python -m pytest tests -q`。在 frontend 目录运行 `npm ci`、`node --test tests/*.test.cjs` 和 `npm run build`。演示版启动后，在 backend 目录运行 `python tests/live_submission_smoke.py --output ../docs/live-submission.json` 可通过真实 HTTP 接口验证四种错误代码和正确代码；脚本每次创建一个独立 smoke_ 测试账号，报告不保存密码和令牌。专用 MySQL 契约测试和样例生成步骤见实施契约。
