# Ottly 本机演示版

当前资料见[文档导航](docs/README.md)。历史研究、已完成计划、阶段验收与设计素材见[历史资料归档](docs/archive/README.md)，其中的技术栈和验收结论仅代表当时版本。当前部署、功能和开发检查以本文件及现行文档为准。

## 启动

在 Windows 上先启动 Docker Desktop，然后双击 start-demo.bat。首次启动会下载并构建镜像，脚本会在本目录生成仅供本机使用的 .env，其中包含随机数据库密码和 JWT 密钥。页面地址是 http://127.0.0.1:3000。

拉取更新后再次运行 start-demo.bat，脚本会重建前后端以应用新代码。启动脚本支持查找 Docker 的用户安装目录和系统安装目录，并输出完整构建步骤。构建中的 `#24` 等编号只是步骤编号，应结合后面的步骤名称判断进度；如果长期停在执行命令阶段，可先在 Docker Desktop 中重启引擎后重试。在 PowerShell 中运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-demo.ps1 -NoBrowser` 可启动并检查服务而不自动打开浏览器。

若 Docker 提示 `WSL is unresponsive`，退出 Docker Desktop 后执行 `wsl --shutdown`，再启动 Docker Desktop。若关闭 WSL 的命令也一直无响应，请保存工作并使用 Windows 的“重启”，之后等待 Docker 引擎就绪再运行启动脚本。不要使用“恢复出厂设置”处理此问题，以免清除数据库卷。

双击 stop-demo.bat 可停止服务。数据库保存在 Docker 命名卷中，停止服务不会删除账号和聊天记录。不要把 .env 上传到 GitHub。

可在本目录运行 docker compose ps 查看服务，运行 docker compose logs backend 查看后端错误。

已有数据库升级本轮契约前，需要备份并运行显式迁移；应用不会用 create_all 自动补旧表列。检查命令为 backend 目录的 `python migrate_submissions.py`。SQLite 使用 `--apply` 自动备份后加列；MySQL 先完成外部备份，再使用 `--apply --backup-confirmed`。完整操作和回退步骤见 [契约 v1 实施与迁移](docs/05-契约v1实施与迁移.md)。

## 注册和登录

注册需要用户名、密码和手机号。登录后页面会验证令牌；聊天记录、职业选择记录和设置接口按当前登录账号隔离。当前未接入短信验证码，所以密码重置入口和接口已停用。请保存演示账号密码。

本机演示版的访问令牌有效期为 8 小时。修改密码、注销账号或后端更换 `JWT_SECRET` 后，现有令牌会失效；清除浏览器登录数据后需重新登录。已在修改前签发的旧令牌不会自动延长，需要重新登录一次取得新的 8 小时令牌。

新注册密码需为 12–128 个字符，后端拒绝部分常见弱密码、单一重复字符以及与用户名或手机号相同的密码；旧账号登录保持兼容。密码使用 Argon2 哈希保存，注册和登录响应不返回密码。此校验不是完整的泄露密码库查询：浏览器密码管理器若提示凭据出现在已知泄露记录中，应使用独立的新密码，不能通过关闭浏览器提示处理。注册密码框使用 `new-password`，登录使用 `current-password`。

关卡编辑器会在每次编辑时把代码和运行输入保存为当前浏览器的本机草稿，按已验证的账号 ID 和题目 ID（包含题目版本）区分。返回关卡、刷新以及退出后重新登录均可恢复，主动清空代码也会保存为空草稿。两个退出登录入口都只清理登录令牌。清除网站数据、更换浏览器或设备不会同步草稿；浏览器拒绝写入或空间不足时，编辑器会提示复制备份。该功能不改变正式提交、判题或通关记录。

### Python 代码编辑器

主线、加练和错题复习使用同一套 Python 编辑器，支持关键字、字符串、数字和注释高亮，以及括号、单双引号自动配对。回车时按 Python 语句延续缩进，块末冒号后增加4个空格；Tab 增加缩进，Shift+Tab 减少缩进，也可选中多行一起调整。

Windows/Linux 使用 Ctrl+Z 撤销，Ctrl+Shift+Z 或 Ctrl+Y 重做；Mac 使用 Command+Z 撤销、Command+Shift+Z 重做。按 Esc 后再按 Tab 可把焦点移出编辑器。运行与提交使用编辑区的当前代码；主线和加练继续按账号、题目版本保存浏览器草稿，复习仍从原错题代码开始。编辑器按需加载，不在其他页面提前下载其依赖。

旧版偏好设置（护眼、音量、通知、语言、时区）已退役，`/api/v1/settings` 及其子路径不再提供服务。新数据库不再创建对应的三张表；已有数据库保留旧表，注销账号时仍在同一事务中清理该账号的历史偏好，不影响其他账号。此次无需删表迁移。

前端保留 Bootstrap CSS，交互由现有 React 组件及原生对话框负责，不再加载 Bootstrap JavaScript。本机研究材料已独立保存，位置与复现说明见[本机研究资料归档说明](docs/research-archive.md)。

## AI 模型

AI 对话按登录账号保留当前会话：切换页面或刷新后会恢复，回复生成中离开页面后也可继续查看。后端服务重启（包括项目整体重启）后自动开启新对话，旧记录仍在“历史记录”和会话下拉列表中；也可以主动点击“新对话”。当前会话指针保留在单进程后端内存中，不依赖浏览器缓存，不修改历史表结构。

对话不再静默截断为最近四轮。当前使用 8192 token 的模型上下文配置，按 UTF-8 字节数保守估算输入容量并预留回复与模板空间，最多保留 20 轮；先达到容量预算或轮数保护时会提示新建对话，并禁止继续向旧上下文发送。该预算是保守保护，不是精确的模型 tokenizer 计数。新建后尚未发送的问题会保留在输入框中。

所有 AI 入口统一使用 DeepSeek-V4.1-Flash，API 模型名固定为 `deepseek-flash`：陪学对话、关前问答、错因诊断与审核、部分失败提示及选择题、加练推荐、无尽挑战出题与审核。模型配置集中在后端 `app/services/error_analysis.py`，不再提供其他模型或本地推理切换。

在项目 `.env` 中设置 [DeepSeek 平台](https://platform.deepseek.com/api_keys) 创建的密钥：

```dotenv
DEEPSEEK_API_KEY=替换为你自己的API密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

密钥只由后端读取，`.env` 已被 Git 忽略，不要写进前端或仓库。保存后运行 `docker compose up -d --build --no-deps backend`。无需安装或启动本地模型服务，也不需要下载模型权重。

陪学对话与关前问答使用非思考模式；错因分析、审核、提示及推荐使用思考模式与 JSON 校验。只展示并保存最终回答，不展示模型的 reasoning_content。聊天会发送当前问题和本会话上下文；编程助教只发送题意、学生代码和公开证据，不发送隐藏测试或参考解。相关请求按 DeepSeek API 用量计费。

密钥缺失、无效、余额不足、限流、网络超时或回答未通过校验时，会保留当前结果并提示重试，不改用其他模型。旧学习记录和历史调研、验收报告保留原样，其中旧模型名称仅描述历史，不代表当前依赖。官方模型说明见 [DeepSeek-V4.1-Flash](https://api-docs.deepseek.com/news/news260910/)。

全部 12 关的关前引导提问页支持输入问题并点击“发送问题”，由 DeepSeek-V4.1-Flash（`deepseek-flash`，非思考模式）结合当前关卡讲解回答，可连续追问，在本次引导的“历史对话”中查看问答。该入口始终使用 DeepSeek，复用后端 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_BASE_URL`。点击“我明白了，继续”可以直接跳过提问，等待回答时也可继续；仍需答对后续知识小测才记录引导完成。调用失败时保留输入供重试，不影响继续。自由问答不创建判题或通关记录，退出或刷新后不保存；当前关卡公开讲解和本次引导最近的自由问答会随问题发送给 DeepSeek。

### 体验编辑页 AI 错因分析

登录后在任意已解锁关卡输入 `print(message)`，点击“运行”或“提交判题”。运行报错后自动分析本次输入；提交失败时先显示判题结果，再自动生成分析。点击编辑器旁的“查看错因分析”查看原因、真实执行证据和相关知识点。“我的错题”复习编辑器也显示运行报错分析。运行成功不判断答案是否符合题目，正式判题仍使用“提交判题”。

错因由真实模型根据当前代码、实际输入、公开输出或异常生成。所有题目共用同一诊断服务，分析不混入历史提交；未来题库题目只需注册为标准题目并复用运行、提交接口。通关后的无尽挑战支持从现有加练题库抽题。

关卡编辑器运行出错时先显示真实执行结果，再等待 AI 分析，模型分析期限为 90 秒；等待期间“提交判题”旁显示“Ottly正在分析错因”。不会再次执行代码，也不会把运行写入错题本或通关记录。模型不可用或分析未通过检查时保留真实执行结果。DeepSeek 调用失败时保留具体原因，不用固定诊断冒充模型输出。模型仍可能误判，`ready` 不代表语义必然正确。

全部测试失败及运行报错仍展示错因、公开依据和相关知识点；部分测试通过时展示简短引导和可选概念小测，选择答案后再展开解释，不生成误区诊断。页面不展示旧三级提示及查看提示按钮，后端历史数据及提示接口保留兼容。

错因消息入口和展开窗口固定在关卡视图右上角，页面滚动后仍可查看；每条新消息到达时入口强调两秒，随后恢复常态。通关后“前往下一关”位于“提交判题”右侧，最后一关不显示下一关按钮。

分析向模型提供字符差异、逐行是否匹配及本次诊断范围，避免把正确输出也当成错误。全关卡及运行错误的真实接口记录由 `python backend/tests/live_global_analysis.py` 生成到本机 `docs/live-global-analysis.json`，该报告未随仓库提供；自动检查来源与接口，语义仍须逐项人工核对。旧降级结果不会自动重算，请刷新页面并重新提交。通关复盘、参考解和下一关入口位于右侧编辑器的判题结果下方。

历史 Qwen 模型验收曾发现边界条件、最大值更新等语义误判，同模型审核未全部拦截，记录见 [历史全局分析验收说明](docs/archive/2026-10-25/global-analysis-validation.md)。该记录不代表当前 DeepSeek 模型的验收结论。

### 错题改对后的加练推荐

12 个主关卡中，同一学生在一次正式判题失败后，修改代码并通过，才会触发加练推荐；首次提交就通过、连续重复提交正确答案、仅运行报错，以及通过加练题都不会触发。触发判断来自已保存的提交记录，切换页面或刷新不会丢失失败历史。

通关结果先保存并显示。66 道加练题来自经过校验的固定题库，36 道集中式题目与 30 道独立题目在运行时统一提供难度、目标误区标签和来源链接。系统先筛选同知识点、已发布、已解锁且尚未通过的题，再按已审核 AI 分析的疑似误区标签、知识点和难度排序；第一版目标难度固定为 1。唯一最佳题直接推荐，只有多道题前三项排名相同时才让编程助教辅助选择。模型不可用、超时或返回非法内容时使用规则第一题（`model=rule`），不影响通关记录。

部分测试通过时返回引导与可选概念小测，不生成错因诊断或误区标签。没有可信标签或标签为 `other` 时，只按知识点、难度和稳定题目 ID 推荐，不认定具体误区。模型只看到并列候选和公开失败证据，不接收来源链接、隐藏测试或参考解，也不生成新题。推荐结果按本次成功提交缓存，重复读取不会再次调用模型；历史推荐继续原样读取，不需要数据库表结构迁移。来源链接用于追踪教学参考，不表示直接改编或复制上游题目。

推荐成功后弹出使用 Ottly 图标的卡片，展示题目名称和简短推荐理由。“去看看”直接进入该题的题目与编辑器，“跳过”或 Escape 关闭弹窗并留在当前关卡。选题期间可继续操作或前往下一关；离开页面、开始新运行或编辑代码后，过期的推荐不会突然弹出。没有合适题目时保留正常通关提示；加练失败、通过或跳过均不改变主线解锁状态。

## 无尽挑战

学习地图在第 12 关后增加第 13 个「∞ 无尽挑战」图标。全部 12 关通过后解锁，点击弹出「开启无尽挑战」，提供「从题库中抽题／从已有题库中选择一道题。」和「让 Ottly 出题／根据你的错题和学习情况，生成一道新的挑战。」两个选择。

题库模式从现有 66 道已发布加练题及当前账号已有的 AI 题中随机抽题，优先尚未通过的题；全部做过后允许重复练习。Ottly 模式复用后端 DeepSeek 配置，根据当前账号近期不同题目的错误记录、可信疑似误区及后来改对情况生成题目；同一道题反复失败只提供一份错误线索，并参考最近生成题目的标题减少重复情境。没有明显薄弱点时提供已学知识的综合练习。

生成流程为「生成候选题 → 检查题目结构 → 执行参考答案和测试 → 检查边界及题意一致性 → 合格后开放作答」。候选包含情境、任务、输入输出格式、数据范围、知识点、参考答案、1–2 个公开样例和 3–6 个隐藏测试。只生成已学范围内的标准输入输出题，可以改变情境、数据范围并组合至多三个知识点。结构检查后通过现有执行器运行参考解，再由单独一次模型调用审核题意与边界，补充 2–4 个边界输入及预期输出；至少一个输入必须不同于原测试。程序交叉执行这些测试，通过后把新增输入纳入隐藏测试。

验证失败最多生成两轮，等待窗口显示当前阶段。模型错误、超时或两轮仍不合格时保留选择窗口，允许重试或切换题库。关闭窗口取消当前等待，不会因迟到回复跳转。生成和审核均调用同一配置模型，执行及一致性检查不能保证题意或答案绝对正确，仍需真实模型和人工语义验收。

两种来源都进入 `/app/endless?problem_id=...`，直接复用加练题页面、编辑器、代码草稿、运行、判题、错因分析及通过后参考解。验证通过的 AI 题按账号保存到 `generated_problems` 表，并自动显示在题库第 12 关后新增的「无尽模式」类别；已有 AI 题也自动归入该类别，无需迁移。刷新和重启后按原版本恢复，可从题库反复作答并保留通关状态。参考解与隐藏测试不随题目下发，其他账号不能读取、运行或提交该题。AI 题失败可进入错题本，注销账号时一并删除。启动后端时创建新增表，不修改现有学习表结构。详细验收见 [无尽挑战实现与验收](docs/archive/2026-10-26/records/2026-10-25-endless-challenge.md)。

独立程序 `backend/write_endless_problem.py` 支持按 Candidate JSON 格式写入 AI 题，执行参考解测试及真实模型审核，合格后使用与在线出题相同的写入函数归入「无尽模式」。文件格式、示例和命令见 [无尽模式写入程序](docs/endless-catalog-writer.md)。

## 当前边界

本演示只监听本机 127.0.0.1:3000。运行与提交接口要求登录，复用原沙箱，在短生命周期子进程中执行；提交限 6000 字符、每用例 3 秒、输出上限 8000 字符。超时会终止执行进程，并明确标记输出未采集。此举解决卡死与输出串扰，并不构成针对恶意代码的操作系统安全隔离；目前只供团队本机演示。

12 关已统一为第 2 关的完整学习页面：情境、知识讲解、任务、样例、代码编辑、运行输入输出、错因分析、判题与学习记录，以及通关后查看参考解。第 1 关无需输入；第 2～12 关使用受控输入及公开、隐藏多测试。失败时使用所配置的编程助教分析；统一明确显示 DeepSeek 调用或内容校验失败。逐关通过后解锁下一关，第 12 关通关后显示课程完成。第 11 关检查列表、for 及常见最大值和排序函数限制，第 12 关额外检查函数重复调用、整数返回值与输入列表不变。旧 `level2` 循环题保留供历史复习，不计为新版第 2 关通关。本轮新增内容与验收见 [12 关接入与验收](docs/archive/2026-10-26/records/07-12关接入与验收.md)。

个人中心按内容区左侧排列，账号信息展示默认头像、昵称、手机号和个性签名。点击“修改昵称”后编辑，使用原“保存账号信息”按钮保存昵称和签名到账号；昵称不改变登录用户名。手机号变更仍需在弹窗中确认当前密码，下方保留修改密码、退出登录及注销账号。资料保存到新增 `user_profiles` 表，后端启动时创建，不修改旧表列；注销账号时一并删除。

正式主线 12 关在代码区提供“执行回放”，按当前代码和输入生成受限的逐行轨迹，不写入判题或成绩；超出教学语法或资源限制时会提示。AI 出题仅在通关后的无尽挑战开放。.env、Docker 命名卷和 AI 模型服务不在 Git 仓库内。第 2 关的内容位置和验收步骤见 [第 2 关接入与验收](docs/archive/2026-10-25/04-第2关接入与验收.md)。

学习接口采用 schema_version=1.0.0，题库校验知识点、难度、题目版本和前置引用；解锁由 prerequisite_problem_ids 决定。提交保存元数据快照，提供规范英文错误码和 failed_tests；历史记录缺失的元数据不推断。分析知识点编号由后端精确映射。队友对接见 [实施契约](docs/05-契约v1实施与迁移.md) 与 [响应样例](docs/contract-v1-examples.json)。

旧版接口、文件职责、三种错误示例、错误处理和测试步骤见 [提交判题与提示接口说明](docs/archive/2026-10-26/records/submission-flow.md)。真实模型验收数据由下方 smoke 脚本生成到本机 `docs/live-submission.json`，该报告未随仓库提供。

## 开发检查

在 backend 目录使用 Python 3.11 虚拟环境安装 requirements.txt 与 pytest，先运行 `python validate_catalog.py --check-solutions`，再运行 `python -m pytest tests -q`。在 frontend 目录运行 `npm ci`、`node --test tests/*.test.cjs` 和 `npm run build`。演示版启动后，在 backend 目录运行 `python tests/live_submission_smoke.py --output ../docs/live-submission.json` 可通过真实 HTTP 接口验证四种错误代码和正确代码；脚本每次创建一个独立 smoke_ 测试账号，报告不保存密码和令牌。专用 MySQL 契约测试和样例生成步骤见实施契约。
