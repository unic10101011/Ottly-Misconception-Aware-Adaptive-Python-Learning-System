# 无尽模式题库与 AI 题目写入程序

题库在第 12 关后显示独立的「无尽模式」类别。当前账号已有及以后生成的 AI 题都会列在这里，显示未通过／已通过状态，点击后复用加练题编辑器。AI 题不会因为考察第 8 关的知识点而混进第 8 关类别。

在线出题继续经过结构校验、参考解执行、模型题意与边界审核及交叉执行，通过后由 `app/services/endless_catalog.py` 的统一写入函数保存。分类读取和抽题直接读取已有的 `generated_problems` 表，无需迁移或复制旧题。原来的 66 道加练题仍保持原分组；无尽挑战的题库抽题也可以抽到当前账号已生成的 AI 题。

## 独立程序

`backend/write_endless_problem.py` 接收 AI 按 Candidate 格式编写的 JSON，执行同样的校验与真实模型审核，随后保存到指定账号的无尽模式类别。失败时不入库；已保存的题目版本不能覆盖。程序不接受输入文件中的账号、题目 ID、审核通过标记，所属账号由操作人通过 `--user-id` 指定，题目 ID 由程序生成。

先按 `docs/endless-candidate.example.json` 的字段编写 JSON。该文件只是格式示例，不会自动加入任何账号。输入格式包含标题、情境、任务、输入输出格式、数据范围、1–3 个已学知识点 ID、1–2 个目标误区标签、难度（1–3）、考察重点、1–2 个公开样例、3–6 个隐藏测试、参考解和解析。测试的 `stdout` 要保留实际输出需要的换行，输入不能重复。使用 UTF-8 编码。

推荐在项目根目录使用已运行的后端容器，复用它的数据库和模型配置。下面的 `123` 应替换为目标账号实际 ID：

```powershell
Get-Content -LiteralPath .\docs\endless-candidate.example.json -Raw -Encoding UTF8 |
  docker compose exec -T backend python write_endless_problem.py --user-id 123
```

如果本地 Python 已安装后端依赖，且环境设置了可用的 `DATABASE_URL`，也可在 backend 目录执行：

```powershell
python write_endless_problem.py --file ..\docs\endless-candidate.example.json --user-id 123
```

程序显式加载项目根目录 `.env`，但已有环境变量优先。Docker 方式的数据库地址由 compose 提供；单独运行时不能仅凭 compose 中的 `DB_PASSWORD` 自动连接数据库。后端需已启动以创建题目表。

成功输出 `status=ready`、类别「无尽模式」及新题 ID；失败输出通用错误与错误类型，不输出密钥或模型响应正文。此命令需要调用配置的 DeepSeek 做题意审核。网页刷新题库即可看到新题；完成全部 12 关后可作答。题目沿用当前账号隔离规则，其他账号不会看到这些生成题。

## 本次验证

无尽流程及题库写入后端共 16 项通过，前端全部 83 项通过，生产构建通过。写入程序验证了成功入库、结构错误、参考解失败、模型审核拒绝、无效账号及不可覆盖版本；分类接口验证了自动归类、通关状态及账号隔离。

已重建本机前后端。容器只读核对确认现有 1 道 AI 题已出现在所属账号的无尽类别，无需重新生成或迁移。浏览器使用当前部署资源及模拟题目接口，确认类别位于第 12 关后、不会重复出现在知识点对应的关卡中、可进入共用编辑器并返回该类别，桌面和手机端显示正常且无页面错误。
