## 接口和持久化

`POST /api/v1/code/endless`，请求为 `{"mode":"catalog"}` 或 `{"mode":"ottly"}`，要求登录且全部 12 关通过。

题库模式返回普通 JSON 的 `data.stage=ready` 和已存在的 `problem_id`。AI 模式返回 NDJSON，每行包含 `code=200` 和 `data`，阶段为 `generating`、`structure`、`executing`、`reviewing`、`ready` 或 `error`。只有 `ready` 包含可作答的题目 ID，其他事件不包含参考答案、测试数据或模型推理过程。

生成及审核通过后，完整固定版本保存到 `generated_problems`（题目 ID、账号 ID、题目 JSON、模型、创建时间）。读取、运行、提交、分析和解答复用原接口，按当前账号解析题目，不向全局 `PROBLEMS` 注册。只有通过该题后才可读取参考解；隐藏测试在判题响应及学习记录中继续脱敏。注销账号时删除生成题。

新表由后端启动时的 `Base.metadata.create_all` 创建，不对旧表加列。已有部署需要重新构建前后端：

```powershell
docker compose up -d --build
```

## 验题边界

1. Pydantic 检查字段、长度、知识点白名单、重复项和测试输入唯一性，AST 解析参考解语法。
2. 使用现有有执行期限的子进程执行器，验证参考解通过所有样例和候选测试。
3. 另一次模型调用审核题意、知识点、输入输出约定及边界，生成至少一个原测试未覆盖的输入。
4. 执行参考解核对全部审核预期输出，审核与执行不一致则拒绝。新输入纳入隐藏测试。
5. 合格后保存并开放。结构、执行或审核失败最多重生成一次；模型服务故障或超时显示错误，学生可以切换题库。

生成与审核使用同一配置模型的两次调用，不能据此声称独立模型审核或题目百分之百正确。当前为团队本机演示，复用现有执行隔离能力，不改变 README 描述的沙箱边界。
