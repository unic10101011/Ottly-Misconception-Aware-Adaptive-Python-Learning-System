# 第 2 关接入与验收

第 2 关“打招呼”使用题号 `greeting-v1`。题面、讲解、样例、参考解、三级提示和测试统一放在 `backend/app/data/greeting-v1.json`。教学原稿仍在 `docs/03-12关题库选型与教学详解.md`，本次接入不修改原稿。

## 六步对应结果

| 步骤 | 已实现的行为 | 验收方式 |
| --- | --- | --- |
| 1. 题目数据 | 独立版本题号、K02 与前置 K01、全部教学内容 | 查看 JSON；课程接口不下发参考解和隐藏测试 |
| 2. 学习页面 | 情境、可折叠讲解、任务、样例、代码编辑器 | 通过第 1 关后进入第 2 关 |
| 3. 输入运行 | 输入框按行供 `input()` 读取；运行不改变通关状态 | 输入 `Sea Otter`，运行正确代码，得到 `Hello, Sea Otter!` |
| 4. 正式判题 | 每个用例独立执行；1 个公开测试、3 个隐藏测试；严格检查空格与换行 | 写死 `print("Hello, Ottly!")` 只能通过 1/4；正确解通过 4/4 |
| 5. 提示与记录 | 失败后逐级提示；模型异常时使用有标识的基础提示；保存提交和提示查看情况 | 查看全部三级提示，再到“我的错题”查看对应记录 |
| 6. 通关与复盘 | 按账号保存进度；通过后可看参考解；第 3 关待开放 | 退出并重新登录，确认第 2 关仍已通关 |

## 手动验收顺序

1. 注册或登录一个本机测试账号。未通过第 1 关时，第 2 关应锁定。
2. 提交第 1 关正确代码，进入第 2 关。
3. 在代码区填写下方正确解，运行输入填写 `Sea Otter`。点击“运行”，应输出 `Hello, Sea Otter!`，但尚不通关。
4. 改为 `print("Hello, Ottly!")` 并提交，应通过 1/4。隐藏测试不展示输入、预期输出、实际输出或异常详情。
5. 依次点击三次提示按钮，检查提示逐级出现。模型不可用时，应显示“本关基础提示”，不能假装是 AI 诊断。
6. 改回正确解并提交，应通过 4/4。关闭成功提示后，查看通关复盘和参考解。
7. 打开“我的错题”，检查错误代码、提示查看记录以及重做入口。重做可以填写运行输入。
8. 退出并重新登录，确认第 1、2 关已通关，第 3 关显示“已解锁·待开放”。

```python
name = input()
print("Hello,", name + "!")
```

## 自动检查

正常开发环境按 README 安装依赖后运行：

```powershell
# backend 目录
python -m pytest tests -q

# frontend 目录
node --test tests/submission-flow.test.cjs
npm run build
```

新增后端覆盖在 `backend/tests/test_greeting.py`，包括输入空格与空行、EOF、常见错解、隐藏数据保护、权限、参考解解锁、旧题兼容、进度持久化和执行器故障不记为学习失败。前端检查包括运行与提交参数区分，以及隐藏测试和提示来源的展示。
