## 教学要求与函数判题

`Lesson` 新增服务端可选字段 `assessment` 与 `function_tests`，前者默认 `output`，后者默认空数组。旧题自动沿用原有输出判题。接口题面与模型输入的白名单不增加这两个字段，数据库结构不变。

第 11 关使用 `list_maximum`：检查列表创建和 for 语法，拦截 max、sorted 的名称引用及 sort 属性。字符串或注释中的同名单词不会触发限制。检查不比较参考解文本，也不声称能够通用识别学生自行实现的排序算法或其他刻意规避方式。

第 12 关使用 `count_at_least`：编辑器提供函数签名、pass 占位及输入输出代码，学生仅补函数体。服务端按 AST 比较函数体以外的框架，允许注释和空白变化。函数必须使用提供的签名；输入输出测试检查完整程序，隐藏函数测试则在沙箱中单独定义函数并连续调用，检查结果、严格整数类型以及列表内容保持不变。这样能拒绝只打印而不返回、提前 return、污染计数、改变列表或依赖外部输入变量等情况。

`function_tests` 每项包含 `case_id` 与至少两次 `calls`；每次含 `scores`、`threshold`、`expected`。函数用例 ID 与普通用例全局互斥。它们始终隐藏，仅公开通过状态，纳入 `total_cases` 与 `failed_tests`。服务端生成调用程序，调用的 True/False 是实际沙箱结果，保存和返回前脱敏。

教学要求失败时不执行程序，返回 `judge.status=wrong_answer`、提交级 `error_type=WRONG_ANSWER`，公开用例错误为 `REQUIREMENT_NOT_MET`，原因在 message。此时 `output_available=false`，前端提示先满足任务要求；不能当作正常运行得到空输出。“运行”仍只检查原代码执行，不应用正式提交的教学规则。

第 8、9 关等题面要求使用对应循环，但除上述检查外，其他题主要按输入输出判题，不通用验证算法结构。

函数接入还修复沙箱模块命名空间：执行代码的 globals 与 locals 使用同一字典，使函数能够按正常 Python 语义访问同一程序中的其他函数和模块变量。进程隔离、时间与输出限制、已有安全检查保持原样。
