# 题库、判题与错题契约 v1.0.0：实施与迁移

日期：2026-10-16。本文件描述本轮已实现的接口，替代旧草案中与此处不同的部分。教学原稿 `03-12关题库选型与教学详解.md` 不作为运行时题库。

## 实施范围

五个批次分别覆盖题库校验、配置驱动解锁与判题结果、数据库快照、错题对接、联调验收。现有第 1 关、新第 2 关和旧循环题使用统一模型。契约实施时没有发布第 3–12 关内容；后续已接入第 1～7 关，其后第 8～12 关亦已完成，当前清单和验收见 `07-12关接入与验收.md`。

模型、模型参数、提示词、生成和审核流程没有调整。`error_analysis.py`、`hint_quality.py` 不改动；规范错误码和编号映射在接口适配层完成。分析接收原有 Problem 与 CaseResult 结构及原始错误名称，且只接收脱敏证据。

## 题库负责人交付

文件位于 `backend/app/data/`：

| 文件 | 职责 |
| --- | --- |
| `knowledge.json` | K01–K12 的名称、定义和经审核的精确别名 |
| `levels.json` | 当前关卡槽位、所绑定的题目版本、待开放关卡的前置关系 |
| `level1.json` | 保持原题 ID、题意和首尾空白比较行为 |
| `greeting-v1.json` | 新第 2 关完整数据 |
| `level2.json` | 旧循环题，不占新版第 2 关槽位；兼容原有提交与复习 |

新题目的基础数据结构由 `Lesson` 定义，以下基础字段必填；后续增加的服务端可选评估字段见 `07-12关接入与验收.md`：

```text
schema_version: "1.0.0"
problem_id: string，最多 100 字符
version: integer >= 1
level_no: integer，1–12
title: 非空 string，最多 255 字符
difficulty: 1 | 2 | 3
knowledge_ids: 非空 string[]
prerequisite_knowledge_ids: string[]
prerequisite_problem_ids: string[]
published: boolean
story: 非空 string
teaching: 非空 {title, text, example}[]
description: 非空 string
starter_code: string，最多 6000 字符
examples: 非空 {stdin, stdout}[]
tests: 非空 {case_id, stdin, expected_output, visibility}[]
comparison: exact | legacy_trim
time_limit_seconds: 3
output_limit_chars: 8000
hints: {level1, level2, level3}
reference_solution: 非空 string，最多 6000 字符
solution_explanation: 非空 string
```

`visibility` 只能是 `public/hidden`。新输入题需有公开与隐藏测试。ID 必须匹配小写短名加 `-vN`，且 N 等于 version；`level1/level2` 为固定历史例外。新题使用 exact 比较：只统一 CRLF 为 LF，其余空格和行末换行精确比较。旧题保留 legacy_trim，不追加“必须使用循环”等新判题约束。

`difficulty`：1 基础，2 巩固，3 综合；由题库负责人指定，不是学生能力分数。知识点引用必须存在。数组内的知识点和前置 ID 不得重复；前置题必须存在，不得自引用或形成循环。case_id 在同一题内唯一。

`levels.json` 中有 problem_id 的槽位从题目读取标题、发布与前置关系，不允许再写第二份前置配置。problem_id=null 是待开放槽位，发布永远为 false，可以声明已知前置题。

开发和发布检查，在 backend 执行：

```powershell
python validate_catalog.py --check-solutions
```

这会加载并校验全部引用，再运行每道题的参考解验证全部正式测试。加载失败时后端拒绝启动，不带病发布题库。

影响题意、输入输出、测试、比较方式、难度、知识点、前置关系或教学含义的修改，应新增题目版本。旧版本保留，不覆盖旧记录、不继承通关。本轮为既有题目补齐初始元数据，保留原 ID 和原判题语义。

## 后端负责人交付

认证沿用 `Authorization: Bearer <access_token>`。以下接口统一带 `/api/v1` 前缀。成功响应外层包含 `schema_version: "1.0.0"`、`code: 200` 和 `data`；运行接口另外保留 msg。认证等不属于本次契约的接口不修改。

| 接口 | 请求／返回 |
| --- | --- |
| `GET /code/knowledge` | data.items 为 `{knowledge_id,name,description}[]`；不暴露内部别名表 |
| `GET /code/levels` | data.items 为 `{id,problem_id,name,published,status}[]` |
| `GET /code/problems/{problem_id}` | 返回公开教学内容、版本、难度、知识点、前置、执行限制与 completed；不返回 tests、hints、参考解 |
| `GET /code/problems/{problem_id}/solution` | 同版本通过后返回 problem_id、version、reference_solution、solution_explanation |
| `POST /code/run` | 请求 `{code,stdin?,timeout?}`；仅试运行，不入库、不通关、不调用分析 |
| `POST /code/submit` | 请求严格只允许 `{problem_id,code}`；正式测试由服务端决定 |
| `GET /code/submissions` | 支持 failed_only、problem_id、limit=1–50（默认20）、offset>=0 |
| `GET /code/mistakes` | 按当前用户和 problem_id 聚合错题，保留通过后的历史 |
| `PATCH /code/submissions/{id}/hints` | `{level:1|2|3}`；原子保存最大查看级别，重复请求不累加 |

状态为 locked/current/completed。所有 prerequisite_problem_ids 都通过才解锁。已有同版本通过记录就保持 completed，后来失败不撤销；未发布题拒绝普通详情、提交和参考解访问。携带有效复习来源的历史复习可继续提交同一旧版本。

运行 code 最多 20000 字符，stdin 最多 8000 字符；timeout 1–10 秒，默认10秒。正式提交 code 1–6000 字符且不能全为空白，每用例3秒。页面仍传3秒。运行错误也使用规范错误码。

正式提交 data：

```text
submission_id: integer
problem_id: string
version: integer
created_at: UTC ISO 8601，毫秒精度，以 Z 结尾
error_type: string | null
judge: ContractJudge
analysis: ContractAnalysis
```

判题字段：

```text
judge.status: accepted | wrong_answer | execution_error | timeout
judge.passed: boolean
judge.passed_cases: integer
judge.total_cases: integer
judge.failed_tests: string[]
judge.cases: {
  case_id: string,
  passed: boolean,
  visibility: public | hidden,
  expected_output: string,
  actual_output: string,
  output_available: boolean,
  errors: {type:string,line:integer|null,message:string}[],
  execution_time: number（秒）
}[]
```

failed_tests 始终从 cases 中 passed=false 的项按原顺序计算，不能由客户端、模型或独立数据库字段指定。总体状态优先级：全部通过 accepted；否则任一超时为 timeout；否则存在执行错误为 execution_error；剩余为 wrong_answer。

规范错误码：

| 错误码 | 含义 |
| --- | --- |
| WRONG_ANSWER | 输出不匹配 |
| SYNTAX_ERROR / INDENTATION_ERROR | 语法／缩进错误 |
| NAME_ERROR / TYPE_ERROR / VALUE_ERROR | 名称／类型／值错误 |
| ZERO_DIVISION_ERROR | 除零 |
| INDEX_ERROR / KEY_ERROR / ATTRIBUTE_ERROR | 索引／键／属性错误 |
| EOF_ERROR / IMPORT_ERROR | 输入耗尽／允许范围内的导入失败 |
| SECURITY_ERROR | 使用禁止操作 |
| OUTPUT_LIMIT_EXCEEDED / TIMEOUT | 输出超限／执行超时 |
| RUNTIME_ERROR | 未细分的学生运行异常 |

通过时提交级 error_type=null；超时优先为 TIMEOUT；执行错误取第一个失败用例的错误码；仅输出错误为 WRONG_ANSWER。中文说明放在 message。原沙箱将缩进合并为语法错误时，接口通过只读 AST 解析还原缩进类别，模型输入不受影响。

隐藏测试清空 expected_output、actual_output、errors，并设置 output_available=false。禁止向学生、历史响应和分析模块发送隐藏输入输出或异常详情；case_id、通过状态和耗时可以提供。提交级错误码在脱敏前确定，保留故障类别而不泄露内容。历史读取时再次脱敏。前端优先根据 visibility 判断“隐藏测试”，再区分“未采集”和真正空输出。

HTTP 错误沿用 FastAPI detail：401 登录问题、403 前置或发布限制、404 不存在或不属于当前用户、409 提示不可查看、422 请求验证失败、503 执行器不可用。503 不生成学习失败记录。200 表示请求处理成功，不保证学生通过。

## 分析适配：本轮不调整模型

模型的原始 AnalysisResult / AnalysisContent 结构保持不变。对外适配新增 content.knowledge_ids，保留原 knowledge_points 文字。二者不是逐项一一对应的数组。

```text
analysis.status: ready | skipped | unavailable | timeout | invalid_response
analysis.source: ai | fixed | null
analysis.model: string | null
analysis.message: string
analysis.content: null 或 {
  suspected_cause,
  evidence: {case_id,field:actual_output|error_message,quote,explanation}[],
  knowledge_points: string[],
  knowledge_ids: string[],
  hints:{level1,level2,level3}
}
```

编号映射仅去除首尾空白、统一大小写后，按字典名称或精确别名匹配；只接受该题 knowledge_ids 与 prerequisite_knowledge_ids 范围内的编号，按首次出现去重。未知或范围外的文本不填编号，无匹配返回 []；不做模糊匹配，也不额外调用模型。新的分析编号在提交时保存，历史读取不按今天的别名重新映射。

ready 保留经原流程验证的内容；非 ready 时 content=null、source=null。通过时 skipped 且 model=null；固定提示 source=fixed 且 model=null。原有第 2 关模型失败回退保持不变。后续前 7 关接入在接口外层增加已审核基础提示回退，具体见 `06-前7关接入与验收.md`。分析意外失败也保留已入库判题；存在可用公开证据时可返回固定基础提示，否则返回 unavailable。

## 错题负责人交付

每次正式提交保存独立记录。新增数据库列 schema_version、problem_version、difficulty、knowledge_ids，保存服务端当时的元数据。接口将 problem_version 输出为 version。与已有题面、标题、代码、判题、分析共同组成提交快照。

历史记录 data.items：

```text
id, problem_id, problem_title, problem_description, code,
schema_version: string | null,
version: integer | null,
difficulty: 1|2|3|null,
knowledge_ids: string[],
judge, analysis: object|null, passed, error_type: string|null,
hints_viewed_max: 0|1|2|3,
review_source_id: integer|null,
resolved_later: boolean,
created_at
```

记录的 schema_version 代表当时保存格式，和响应外层的当前接口版本分开。历史记录未知元数据保留 null；未知知识点返回 []。不得用当前题库值回填页面，也不得默认难度为1。旧 judge JSON 缺少 failed_tests 时读取派生；旧错误名称读取规范化；旧分析未知知识点不猜测编号。含隐藏测试依据的旧分析不展示。

复习提交沿用 `X-Review-Source-Id`，只能关联当前用户、相同 problem_id 的失败记录。历史返回 review_source_id，方便复习轨迹对接。没有来源的普通提交不算复习。错题按 problem_id（含版本）分组，不跨版本合并；resolved_later 只看该次失败后的同版本通过记录。错题聚合新增 version、difficulty、knowledge_ids，取最新提交快照；不是读取当前题库。

错题页已展示快照版本、难度、知识点、错误码和失败测试；旧记录显示“历史记录未提供”。related_questions 仍为 []，没有新增推荐功能。

## 数据库迁移与回退

现有 create_all 不能给旧表补列。应用会检测缺列并停止启动，提示显式迁移。不要以删库、重建卷代替迁移。

先停止写入并确认 DATABASE_URL 指向正确数据库。backend 目录执行：

```powershell
# 只检查，不修改
python migrate_submissions.py

# SQLite：在原数据库旁自动建立 .bak 备份，然后增加列
python migrate_submissions.py --apply

# MySQL：先按团队流程备份并验证恢复；确认后执行
python migrate_submissions.py --apply --backup-confirmed
```

脚本只增加缺少的可空列，可以重复执行；MySQL DDL 中断后再次执行会跳过已有列。不会推断旧记录的版本、难度或知识点。MySQL 的 --backup-confirmed 是操作者声明，不是脚本已经完成备份的证明。DDL 不能靠事务整体回滚。

Compose 使用者先构建新 backend 镜像，在 db 已启动的情况下运行检查与迁移：

```powershell
docker compose build backend
docker compose run --rm --no-deps backend python migrate_submissions.py
# 完成外部备份后
docker compose run --rm --no-deps backend python migrate_submissions.py --apply --backup-confirmed
docker compose up -d backend
```

回退代码时保留新增列，旧程序会忽略它们；不要删除快照列。若必须恢复整库，应停止应用，使用验证过的备份恢复，并明确备份之后的新记录会丢失。回退前先另存升级后的数据库。

本轮只升级此前本机临时 SQLite 预览库，并在独立测试 MySQL 中验证；未迁移团队的实际 MySQL 项目库。SQLite 备份位于 backend/.pytest_cache/，不进入 Git。

## 验收与复现

```powershell
# backend：正常 Python 3.11 环境安装 requirements.txt 与 pytest 后
python validate_catalog.py --check-solutions
python -m pytest tests -q

# frontend
node --test tests/*.test.cjs
npm run build
```

MySQL 迁移测试通过 CONTRACT_TEST_MYSQL_URL 指向专用 `ottly_contract_test_*` 数据库后执行 `tests/test_submission_migration.py`。该测试会创建并清理 learning_submissions 表，不得使用项目库。未配置时仅该 MySQL 测试跳过。

另可在专用 MySQL 库设置 DATABASE_URL 后执行：

```powershell
python tests/mysql_contract_smoke.py ../docs/contract-v1-examples.json
```

脚本验证登录、前置拦截、真实判题、错误码、元数据快照、模型未配置状态、固定提示、复习来源及账号隔离，只输出测试结果，不导出密码或令牌。生成文件是实际接口样例，ID、耗时和时间可变化；不是模型教学效果验收报告。

自动测试覆盖新增版本不继承进度、旧记录未知元数据、隐藏数据二次脱敏、别名精确映射、快照不随题库变化、执行器故障不记学习失败，以及 SQLite/MySQL 旧表迁移的重复执行和数据保留。浏览器联调另验证旧错题可打开，新复习提交可展示快照。

2026-10-16 本轮验收结果：题库 3 道参考解全部通过；后端 136 项测试全部通过（含独立 MySQL 测试），前端 16 项测试通过，生产构建成功。独立 MySQL HTTP 测试完成 6 次提交并通过快照、复习关联、账号隔离检查。浏览器验证了迁移前记录未知元数据、新复习记录快照、规范错误码和三级提示编号映射。

实际测试运行时为本机 Python 3.14 和 MySQL 8.0.44；Compose 默认 MySQL 8.4 镜像未在本轮启动。部署环境仍应按上述步骤备份、迁移和验证，不把独立测试库验收当作项目库已经升级。模型测试采用既有模拟响应或固定提示回退，没有重新做真实模型教学效果评估。

## 12 关发布时的合并更新

本轮发布保留远端 main 的快速判题与分步分析：提交先返回真实判题，analysis=preparing 时调用 `POST /api/v1/code/submissions/{submission_id}/analysis` 获取提示。具体状态、耗时字段与权限见现行对接契约。此变化不新增数据库列。12 关内容接入未重新调整模型，远端已有的提示改进保持不变。
