## 0. 一句话结论

**不要把它继续做成"编程闯关 + AI 聊天框"，而要改造成「生成式 AI 驱动的自适应编程学习闭环」。**

具体是：**执行证据做判据、迷思规则库做错因、生成式关卡工厂做内容、可解释知识追踪做自适应、答案感知提示闸门做教学**——让大模型在闭环里承担四个**受约束的生成职责**，而不是当一个可以被任何人替换的聊天窗口。

理由是双重的：
1. **赛题层面**——这是**生成式人工智能**主题赛事，"生成"能力（生成题目/提示/诊断/路径）比"分析"能力更契合评委预期；而现行作品里 AI 与判题完全脱节，正踩在评分细则"避免算法与软件脱节"的反面。
2. **产品层面**——"关卡制编程闯关"赛道已被 CodeCombat / Tynker / 编程猫 / CodeMonkey 占满，正面竞争没有胜算；唯一能建立壁垒的是**内容自生产能力 + 个性化诊断能力**。

## 1.5 四条外部约束（决定产品形态，优先级高于任何技术偏好）

### ① 政策红线：小学生不能"独自使用开放式内容生成"

- 教育部《中小学生成式人工智能使用指南（2025 年版）》要求**禁止小学生独自使用开放式内容生成功能**
- 《生成式人工智能服务管理暂行办法》要求防范未成年人"过度依赖或沉迷"
- 《未成年人网络保护条例》对不满十四周岁个人信息设监护人同意等要求

**→ 直接推论：当前那个独立的"AI 对话页"必须删掉。** 它恰好就是政策禁止的形态——开放式、无约束、可由小学生自由对话。

**→ 替代形态：受关卡上下文约束的封闭式生成。** AI 只在"判题失败"这一刻出现，输入被限定为 `当前关卡 + 学生代码 + 失败用例 + 命中的迷思规则`，输出被限定为 `错因诊断卡 + 分级提示`。

这一步同时解决三件事：合规、消除"AI 与核心功能脱节"的扣分、把 AI 变成不可替换的核心部件（因为提示必须依赖判题产出的失败用例）。

### ② 竞品格局：AI 进核心闭环是**产品级空白**

| 层次 | 是什么 | 代表 | 在学生学习闭环内？ |
|---|---|---|---|
| Layer A | 教师侧效率工具 | Code.org AI 教学助手（生成材料、辅助评分）、CodeCombat 教师仪表盘 | ❌ 不在 |
| Layer B | 学生侧对话/提示，**与判题解耦** | Tynker Copilot（自研微调 Llama 2）、CodeCombat AI Hints、Khanmigo | ⚠️ 在，但**不知道**学生当前代码与错在哪 |
| **Layer C** | **判题 / 错因诊断 / 自适应出题** | **只有论文原型，无产品级实现** | ✅ ——**这就是空白** |

四条关键事实：

- 国内头部（编程猫、核桃编程、猿编程、讯飞等）的 AI 叙事多为"双师""全链路赋能"级**话术**，缺少可验证的闭环细节（注：多来自企业新闻稿，无第三方验证）
- ACM 文献指出自动评测工具（AAT）的反馈"**往往过于简陋，通常只显示测试通过或失败**"——与我们现在的字符串比对属于**同一类问题**，说明这不是我们独有的粗糙，而是行业公认短板
- 《Don't Judge Code by Its Cover》证明 **LLM 判代码存在系统性偏见**（受变量命名、代码风格影响）→ **纯靠 LLM 判题同样危险**，必须"规则 + 执行 + LLM"混合
- 家长实测反馈 AI 学习机"**把孩子写的 7 误判成 9**"→ **准确率是少儿产品的生死线，一次误判就会摧毁家长信任**

### ③ 反面教训：无护栏的 AI 会**损害**学习

PNAS《Generative AI Without Guardrails Can Harm Learning》（高中数学场景）发现：无约束使用 AI 的学生，**撤掉 AI 后成绩反而更差**；而按教学法定制的 AI 导师让参与度翻倍。

→ "**不给答案、只给最小提示、绑定课程进度**"是**设计红线**，不是可选项。这也正好是对"为什么不直接用 ChatGPT"的正面回答。

### ④ 一句话抓住评委注意力

> 评委最容易识别的差异不是"你用了大模型"，而是"**AI 的输出直接改变了下一个学习动作**"。

把 AI 从独立聊天页搬进"判题失败"的那一刻，用「**错因标签 → 最小提示 → 变式题**」三段闭环呈现。

## 2. 现状诊断（均为实测，非推测）

### 2.1 🔴 致命：沙箱可被完全逃逸

`backend/app/services/sandbox/` 的防护形同虚设。实测攻击链：

```python
g = getattr                    # ① 别名赋值
subs = g(g(g(1,'__class__'),'__mro__')[1], '__subclasses__')()   # ② 拿到所有子类
# ③ 经 _wrap_close.__init__.__globals__ 取得 __builtins__['open']
# ④ 读取宿主机任意文件
```

实测输出：

```
AST 安全检查通过(未被拦截): True
subclass_count= 300
has_wrap_close= True
REACHED_OS_MODULE= True
FILE_READ_OK: ; for 16-bit app support [fonts] [extensions] [mci extension
```

两个根因：

- **`visit_Call` 只检查函数名是 `ast.Name` 的情况**。`g = getattr` 一赋值，`g(...)` 就不再被识别为危险调用。拦的是"名字"，不是"函数"。
- **`str.format` 的字段访问在运行时解析**，AST 里只是字符串常量。实测 `'{0.__class__.__mro__}'.format(1)` 输出 `(<class 'int'>, <class 'object'>)`，`visit_Attribute` 根本看不到。

后果：任何学生（或任何能调接口的人）都能在服务器上读任意文件、执行任意命令。赛题"作品要求"第 1 条明写 **无重大技术缺陷**——这一条会把技术实现分直接压进 0–6 档。

**顺带发现**：`turtle` 能 import（它内部传递依赖了被黑名单拦截的 `tkinter`），说明**白名单不检查传递依赖**；`pygame` 在白名单里但**根本没安装**。

### 2.2 🔴 致命：超时机制是假的

`sandbox.py` 用 `thread.join(timeout)`，超时后线程**无法终止**。实测 `while True: pass`：

```
run_code 返回耗时: 2.04s (设定超时 2s)
内部线程数: 执行前=1 执行后=2   ← 线程未回收
```

接口 2 秒正常返回，看起来没问题，但进程内多了一个永久烧 CPU 的线程。反复提交即可打满服务器。这是可直接被判为"运行不稳定"的缺陷。

### 2.3 🔴 认证形同虚设（且涉及未成年人数据合规）

| 位置 | 问题 | 后果 |
|---|---|---|
| `app/core/auth.py` | `SECRET_KEY = "your-secret-key-here"` | JWT 签名密钥是默认占位符，**任何人可伪造任意用户令牌** |
| `app/api/auth.py` `/auth/reset-password` | 只凭手机号即可重置密码，**无任何验证码校验** | **任意账号接管** |
| 全部业务接口 | 没有任何 JWT 依赖注入 | API 实际处于未认证状态 |
| `app/api/ai.py` | `user_id=1` 写死 | 多用户对话记录互相可见 |
| `app/api/auth.py` `/auth/me` | 返回硬编码测试数据 | 未实现 |

作品面向**未成年人**，涉及儿童个人信息。这不是"以后再修"的问题，而是赛题要求第 6 条（符合法律法规）的硬门槛，也让"合规、数据不出校园网"这个本可以打的卖点变成反噬点。

## 4. 七个候选创新方向（逐个评估）

> "创新档位"按评分表措辞对齐：**14–20**＝开创性/全新架构；**7–13**＝显著改进、独特方案；**0–6**＝常规优化。

### 方向 1 · 行为等价判题：把判据从"输出相等"换成"行为等价"

**做什么**：每道题不再只存一个 `expectedOutput` 字符串，而存**一组隐藏测试用例 + 参考解集合**。学生代码在沙箱里对多组输入执行，比对**行为**而非打印文本。输出比对降级为"快速预筛"。

**为什么是必须的**：现在 `print('Hello, World!')` 之外几乎任何写法都可能判错。这是产品可用性的底线问题，也是后续一切 AI 能力的地基。

**关键设计**：判题结果定义为三元组 `(运行结果, 反例, 结构指纹)`
- *运行结果*：隐藏用例通过率（部分分，天然支持"5 过 3"）
- *反例*：具体哪组输入让程序行为错误——**这是错因诊断的证据**
- *结构指纹*：AST 归一化后判断"是否与某已知错误族同型"

**创新档位**：7–13（显著改进）。单独看不算开创，但它是方向 2/5 的前提。
**工作量**：中。**依赖**：修好的沙箱。

---

### 方向 2 · 迷思概念诊断：规则库 + LLM 归类（⭐ 核心差异化）

**做什么**：诊断"**思维错在哪**"，而不是"第几行语法错"。例：

> 学生写 `for i in range(1, 100)` 求 1–100 的和
> ❌ 竞品/现状：`预期输出 5050，实际输出 4950`
> ✅ 本方案：**「循环边界理解错误（off-by-one）」** — 证据：隐藏用例 n=100 时结果为 4950，差 100；命中的迷思规则 `RANGE_UPPER_EXCLUSIVE`；建议反问："`range(1,100)` 会依次产生哪些数？最后一个数是多少？"

**技术路线**（学术上已有支撑，见 §7 引用）：
1. **AST / Datalog 风格规则库**检测 K-12 常见迷思——可解释、可人工审核、**不需要训练数据**
2. 建立**9 类 K-12 Python 错误分类体系**：语法与缩进 / 名字与作用域 / 类型混淆 / 循环边界与终止 / 控制流与嵌套 / 函数与返回 / 数据结构与索引 / I/O 与格式化 / 算法意图错（前 8 类规则可覆盖，第 9 类必须靠执行反例）
3. **LLM 只在规则命中之后介入**：把「执行反例 + 命中的规则」喂给模型，输出归类、置信度与教学措辞；低置信度**回退规则，不强行作答**

**为什么得分高**：
- 学术调研明确指出——**面向 K-12 Python 的公开迷思标注数据集是空白**。自建 300–800 条带标签提交集本身即可作为贡献点写进材料。
- 竞品基本停留在"报错信息翻译成人话"，**做到"迷思归因 + 教学反问"的极少**。这是能讲清楚的差异化。
- 规则优先保证**可解释**，演示时能逐条讲清"为什么这么判"，而不是"模型说的"。

**创新档位**：14–20。**工作量**：中高（规则库需人工积累，但可增量迭代）。

---

### 方向 3 · 生成式关卡工厂：一键出题 + 三重验证准入（⭐ 最契合"生成式AI"赛题）

**做什么**：教师/教研输入一个知识点（如"for 循环累加"），系统**生成一整关**：题面、故事包装、脚手架代码、参考解、隐藏测试用例、L1–L4 提示阶梯。经自动闸门审核后入库。

**准入闸门（关键，决定可靠性）**——照搬 Meta TestGen-LLM（FSE 2024）的工业做法："生成 → 执行 → 只保留有增益的"：

| 关卡 | 校验 | 不通过则 |
|---|---|---|
| ① 参考解自洽 | 生成的参考解必须**通过全部生成的测试用例** | 丢弃重生成 |
| ② 区分度 | 测试用例必须能**区分**预置的错误解与参考解 | 补生成测试 |
| ③ 质量闸门 | 题意清晰度、难度标签、是否与已有题重复 | 转人工审核 |

**为什么必做**：
- **直接解决"只有 2 关"这个功能完整性硬伤**——而且是从根上解决：题库从此可自增长，不再受人手限制。
- **命中行业最大痛点**：内容生产成本是编程教育最重的成本项。能自动化生产内容 = 可讲商业价值。
- **这是"生成式 AI 大赛"最对味的方向**——评委看的就是"生成"能力被真正用在核心价值上。

**创新档位**：14–20。**工作量**：中（闸门逻辑可复用方向 1 的沙箱设施）。

---

### 方向 4 · 可解释知识追踪 + 自适应路径

**做什么**：为每个**知识点**（而非关卡）维护掌握度，用 BKT（每知识点 4 参数）+ 贝叶斯 IRT（题目难度）驱动选题；前端用"知识树/雷达图"可视化学情，并给出**可解释的推荐理由**（"你连续两次在循环边界出错，接下来练这题"）。

**关键工程判断——不要上深度模型**：学术调研结论明确，在**数据稀疏**时贝叶斯化 IRT 类模型反超神经网络；DKT/AKT 需要千级以上用户，你的规模会过拟合。BKT + IRT 参数少、可解释、冷启动友好，而且"能讲清为什么推这道题"本身就是"AI 与功能契合度"的加分项。

**冷启动方案**：新用户先做 6–10 道跨知识点**前测**直接估计能力；按年级/是否有 Scratch 经验给先验；同关卡族共享技能先验；**难度分档（易/中/难）代替连续能力值**，更鲁棒且不需要大样本。

**创新档位**：7–13（方法经典，创新在"可解释 + 与生成式出题联动"的产品化）。**工作量**：中。

---

### 方向 5 · 答案感知的分级提示闸门（⭐ 与 ChatGPT 的正当差异点）

**做什么**：把 AI 从"问答框"改成"**不给答案的引导者**"，输出 L1–L4 递进提示：

| 级别 | 内容 | 解锁条件 |
|---|---|---|
| L1 | 概念提醒（"循环要有终止条件"） | 默认 |
| L2 | 定位到具体行/变量（引用**学生真实报错行与变量值**） | 1 次失败 |
| L3 | 伪代码骨架 | 2 次失败 |
| L4 | 可运行片段 | **连续 3 次失败后才解锁，且限次** |

**三重防泄露闸门（这是可验证的工程约束，不是口号）**：
1. **必须引用真实证据**——提示必须带上学生代码的实际报错行与变量值，禁止脱离代码泛泛而谈
2. **答案相似度闸门**——生成后与参考解做 AST/相似度比对，超阈值**自动降级重写**
3. **规则模板优先**——高频错误（缩进、`input()` 返回字符串、off-by-one）直接用人工审核过的模板，LLM 只负责把模板措辞贴合学生代码，把幻觉面缩到最小

**理论合法性**（答辩会被问）：学习科学的"**帮助困境 / assistance dilemma**"指出——给太多帮助会削弱学习。分级提示不是产品偷懒，而是有理论依据的教学设计。这让你可以正面回答"为什么不直接让 ChatGPT 讲答案"。

**创新档位**：14–20。**工作量**：中。已有直接对标的前沿工作（K-12 分级提示，见 §7）。

---

### 方向 6 · 代码驱动角色行为：把画布变成判题载体

**做什么**：学生代码不再只是 `print`，而是**驱动小海獭在关卡里行动**（`turtle` 风格网格世界）：走到目标、收集宝物、绕过障碍。判题自然变成"**行为验证**"——天然接受一题多解。

**实测可行性**：`turtle` 在现有沙箱里**能正常 import 并执行**（已实测通过）。但发现一个明确的**产品缺陷也是机会**：

> 学生画出来的图形，**当前完全不会回传给前端**——`run_code` 只返回 stdout 文本。也就是说，即使学生成功绘图，屏幕上什么都不会出现。

改造点很清楚：**把绘图结果渲染成图片/矢量回传前端展示**。这是一个工作量可控、演示效果极好的功能。

**创新档位**：14–20（体验与交互层面的开创性）。**工作量**：**最大**（需要画布渲染管线 + 关卡编辑器 + 图形化判题）。
**建议**：作为**第二期/演示亮点**，不要在核心闭环（方向 1/2/3/5）之前投入。

---

### 方向 7 · 多模态入口：语音提问（加分项）

K-12 用户**打字慢**是真实痛点。本地 ASR（Whisper 系）让孩子按住说话即可提问，同时天然契合赛题"多模态交互软件"的范围。成本低、演示直观。**建议作为体验加分项，非核心。**

---

## 5. 推荐组合：一条完整的"测—诊—学—练"闭环

不要七个都做。**做 1+2+3+4+5 构成闭环，6 作为演示亮点，7 作为体验加分**：

```
学生提交代码
   │
   ├─▶ ① 沙箱行为等价判题 ────────── 判据：隐藏测试用例（部分分）
   │        └─ 产出：通过率 / 反例 / 结构指纹
   │
   ├─▶ ② 迷思规则库 + LLM 归类 ───── 错因："循环边界理解错误"
   │        └─ 产出：错误类型标签 + 证据链 + 教学措辞
   │
   ├─▶ ③ 可解释知识追踪（BKT+IRT）── 更新该知识点掌握度
   │        └─ 产出：掌握度 + 可解释的推荐理由
   │
   ├─▶ ⑤ 答案感知分级提示（L1–L4）── 引导而非给答案
   │        └─ 三重闸门：引用真实证据 / 相似度闸门 / 模板优先
   │
   └─▶ ③ 生成式关卡工厂 ──────────── 薄弱知识点 → 现场生成变式题
            └─ 三重准入：参考解自洽 / 区分度 / 质量闸门
```

### 配套的关键产品决策：**删掉独立的 AI 聊天页**

这不是可选项。理由已在 §1.5① 说明——独立开放式聊天页既违反政策，又是"AI 与核心功能脱节"的根源。

改造后 AI 只出现在**判题失败的那一刻**：

```
判题失败
  └─▶ 错因诊断卡（规则命中 + 失败用例证据 + LLM 措辞）
        └─▶ [我要提示] → L1 → L2 → L3（L4 需连续 3 次失败解锁，且限次）
              └─▶ [再试一次] 或 [来道同类题] → 生成式变式题
```

这条链路让 AI 的每一次输出都**直接触发下一个学习动作**，而不是停在一段聊天记录里。

**一句话产品定位**：

> 面向 K-12 的**生成式自适应 Python 学习智能体**：以行为等价判据保证判题可靠，以迷思规则库实现可解释错因诊断，以可解释知识追踪驱动个性化路径，以大模型在受约束条件下生成关卡、提示与教学反馈，形成"测—诊—学—练"闭环，**全流程可在校园内私有化部署**。

**这段话同时回答了三件事**：AI 用在哪（四个生成职责）、为什么可靠（每个 AI 环节都有非 AI 兜底与证据链）、为什么合规（数据不出校园网）。

## 5.5 创新点清单（可直接用于参赛《创新点与差异化优势》材料）

### 判断标准：什么才算"创新点"

按评分表措辞，一个能得分（14–20 档）的创新点必须同时满足三条：

1. **相对竞品是新的** —— 不能是"别人也这么做"
2. **相对自己的现状是质变的** —— 不能是"把某处优化了一下"
3. **能被验证的** —— 必须有可量化指标，而不是形容词

反之，**"我们用了大模型""我们加了 AI 聊天"不构成创新点**——这是 0–6 档的典型表述。

以下 14 个创新点分三层：**第一层是答辩主线，必须讲透；第二层各对应具体评分项；第三层性价比高、锦上添花。**

---

### 第一层 · 三个核心创新点（答辩主线）

#### ⭐ I1 · 执行证据锚定的判题架构（LLM 不做裁判）

| | |
|---|---|
| **现状** | 字符串相等比对，任何"写法不同但正确"的解一律判错 |
| **创新点** | 三层架构：**L0 确定性层**（AST 归一化指纹接受多解 + 隐藏用例执行 + 规则匹配）→ **L1 生成层**（仅未命中时调模型）。**模型永远不拥有判题权** |
| **对比竞品** | 竞品要么 AI 与判题解耦（Layer B），要么直接让 LLM 当裁判——而《Don't Judge Code by Its Cover》证明 **LLM 判代码有系统性偏见**（受变量命名、风格影响） |
| **可验证指标** | L0 拦截率（目标 60–80%）、误判率、**假阴性率**、平均判题延迟 |
| **对应评分** | 创新性、技术实现 |

#### ⭐ I2 · "受约束的生成"闭环：三重闸门机制

| | |
|---|---|
| **现状** | 生成式 AI 在教育场景的普遍问题是"生成即呈现"，幻觉直接暴露给学生 |
| **创新点** | **所有 AI 生成物必须过闸门才允许呈现或入库**：关卡生成物要过「参考解自洽 / 区分度 / 质量」三重准入；提示要过「证据引用 / 答案相似度 / 模板优先」三重防泄露 |
| **对比竞品** | 这是**机制层创新**而非功能层——把"生成能力"和"可信度"用工程手段焊在一起，正好对应"生成式人工智能"大赛主题 |
| **可验证指标** | 生成物入库通过率、**幻觉率**、**提示泄露率**、教师驳回率 |
| **对应评分** | 创新性（主）、技术实现 |

#### ⭐ I3 · 迷思概念诊断（不是"报错翻译"）

| | |
|---|---|
| **现状** | `预期输出 5050，实际输出 4950` —— 只告诉你"错了" |
| **创新点** | 输出**思维误区归因**：`「循环边界理解错误（off-by-one）」` + 证据（隐藏用例 n=100 时差 100）+ 命中规则 `RANGE_UPPER_EXCLUSIVE` + 教学反问 |
| **对比竞品** | ACM 文献指出自动评测工具反馈"**往往过于简陋，通常只显示测试通过或失败**"——这是**行业公认短板**；而迷思规则化检测在**产品级完全没有实现**（Layer C 空白） |
| **可验证指标** | 错因归类准确率（人工标注集）、9 类错误覆盖率 |
| **对应评分** | 创新性（主）、应用价值 |

---

### 第二层 · 支撑性创新点（各对应具体评分项）

#### I4 · 不对称判题策略（专治假阴性）

> L0 判定"通过"时**直接通过、不送模型复核**；只有"不通过"或无法归类时才调模型，且**模型永远无权把"不通过"翻转为"通过"**。

教学产品最致命的错误是"把对的判成错的"——家长实测反馈过 AI 学习机"把孩子写的 7 误判成 9"。这个不对称设计用架构手段消除了该风险类别。**可验证指标：假阴性率。**

#### I5 · 答案感知的分级提示 + 三重防泄露闸门

L1 概念提醒 → L2 定位到行/变量 → L3 伪代码骨架 → **L4 需连续 3 次失败才解锁且限次**。生成后做**参考解相似度闸门**，超阈值自动降级重写。

**为什么站得住**：① 学习科学的"**帮助困境（assistance dilemma）**"指出给太多帮助会削弱学习；② PNAS 研究证实**无护栏 AI 会让撤掉 AI 后成绩更差**；③ 直接对标 K-12 分级提示的前沿工作。
**为什么是差异化**：这是与 ChatGPT 的**正当差异点**——ChatGPT 给答案，我们给阶梯。
**可验证指标：提示泄露率。**

#### I6 · 生成式关卡工厂（内容自生产）

教师输入一个知识点 → **生成整关**（题面 + 故事包装 + 脚手架代码 + 参考解 + 隐藏测试 + L1–L4 提示阶梯）→ 过三重准入闸门 → 入库。

**一石三鸟**：① 根治"只有 2 关"的功能完整性硬伤；② 命中编程教育**最重的成本项**（内容生产）；③ 是"生成式 AI"主题最直接的得分点。
**可验证指标：单关生成耗时、入库通过率、难度分布。**

#### I7 · 可解释知识追踪（小样本下的正确选择）

BKT（每知识点 4 参数）+ 贝叶斯 IRT（题目难度）+ **前测冷启动**。前端以知识树/雷达图可视化学情，并给出**可解释的推荐理由**（"你连续两次在循环边界出错，所以推这道题"）。

**为什么是创新**：学术调研结论明确——**数据稀疏时贝叶斯 IRT 反超神经网络**，DKT/AKT 需要千级以上用户，本项目规模会上过拟合。而"能讲清为什么推这道题"本身就是"AI 与功能契合度"的加分项。

#### I8 · 端侧分层推理架构（算力约束下的工程创新）

规则层拦掉 60–80% → 窄任务用微调小模型（1.5B）→ 宽任务用 7B Q4 → 全部跑在**单张 8GB 消费级显卡**上，**零 API 成本、断网可用**。

这不是"退而求其次"，而是一个**可复制的低成本私有化范式**——把"必须上云"的假设打破，本身就是架构创新。

---

### 第三层 · 体验与模式创新（性价比高）

#### I9 · AI 出现在"判题失败的那一刻"，而不是一个独立页面

**交互范式的改变**：删掉 AI 聊天页，改为判题失败界面内的「错因诊断卡 → 分级提示 → 来道同类题」。

**为什么重要**：评委最容易识别的差异不是"你用了大模型"，而是"**AI 的输出直接改变了下一个学习动作**"。同时它**解决了政策合规问题**（禁小学生独自使用开放式内容生成）。

#### I10 · 代码驱动的行为化判题（turtle 画布回传）

学生代码驱动小海獭在关卡里行动，判题变成**行为验证**——天然接受一题多解。

**实测发现的高性价比改造点**：`turtle` 在现有沙箱里**能正常执行**，但**绘图结果完全不回传前端**——学生成功绘图后屏幕上一片空白。补上画布渲染回传，工作量可控、演示效果极好。

#### I11 · 中文友好输入层

非英语母语者学编程存在**额外认知负荷**（有文献支持）；Python 的英文关键字、**英文报错**、打字速度是从积木过渡到文本的明确障碍。
→ 本地模型做「**中文报错解读 + 关键字中英对照 + 补全/填空式编码**」。低龄与农村校刚需，竞品普遍没做好。

#### I12 · 校园私有化"判题 + 诊断"一体机

**数据不出校园网** + 断网可用。政策侧（防沉迷、禁小学生自由生成、未成年人个人信息保护）与校园采购侧双重刚需。
**合规本身就是卖点**——英国曾有报告发现课堂 AI 应用嵌入色情网站追踪器，这类事故让"数据不出校"成为采购硬指标。

#### I13 · 教师端学情看板 + 班级「迷思热力图」

不只报告分数，而是指出**集体性思维误区**（"本班 60% 学生在循环边界出错"）。教师是校内预算与口碑的关键决策者，这是 B 端付费理由。

#### I14 · K-12 Python 迷思标注数据集（附带学术贡献）

现有迷思数据集多为大学 CS1，**面向 K-12 Python 的公开标注数据集是空白**。自建 **300–800 条**带错误类型标签的提交集，本身即可作为独立贡献点写进材料。

**数据来源建议**：优先用**规则层合成**（在正确解上做 AST 层错误注入：off-by-one、缩进、类型、边界），零版权风险、可无限扩充，且 `error_helper.py` 的错误分类就是天然的标注 schema。**避免用闭源大模型蒸馏数据**——既有服务条款风险，也对"自主知识产权"主张不利。

---

### 创新点强度分级（诚实版）

| 强度 | 创新点 | 说明 |
|---|---|---|
| **开创性（14–20）** | I2 三重闸门机制 · I3 迷思诊断 · I5 分级提示闸门 | 竞品无对应实现，机制层创新 |
| **显著改进（7–13）** | I1 判题架构 · I4 不对称策略 · I6 关卡工厂 · I7 知识追踪 · I9 交互范式 · I10 行为化判题 | 单看有先例，但组合与工程落地是新的 |
| **支撑/加分** | I8 分层推理 · I11 中文输入层 · I12 私有化 · I13 学情看板 · I14 标注数据集 | 增强叙事与完整度，不单独作为主创新 |

> **注意**：I1（判题架构）单独看属于"显著改进"而非开创——因为多用例判题在教育系统里已有先例。它的价值在于**是 I2/I3/I5 的前提**，应作为"技术基座"讲，而不是作为头号创新点讲。**答辩主线应该是 I2 + I3 + I5。**

### ⚠️ 三个必须避开的"伪创新"

| 伪创新 | 为什么不得分 |
|---|---|
| "我们接入了大模型 / 我们有 AI 聊天" | 0–6 档典型表述。接模型不是创新，**用模型改变了什么才是** |
| "我们把界面做得更好看 / 加了动画" | 属于常规优化，产品设计投入值得讲，但归入"体验优化"而非"技术创新" |
| 堆砌功能清单（加了语音、加了排行榜、加了徽章） | 功能数量 ≠ 创新性。评委看的是**AI 是否改变了核心流程** |

### 一句话创新主线（建议直接作为答辩开场）

> 我们不是在编程闯关旁边放了一个 AI 聊天框，而是**用生成式 AI 重建了"测—诊—学—练"闭环**：
> **判题靠执行证据、错因靠迷思规则、内容靠生成工厂、引导靠分级提示**——
> 而**每一次生成都必须通过可执行证据与相似度闸门**，全部跑在校园内一张 8GB 显卡上，断网可用。

## 6. 受 8151 MiB 显存约束的技术选型（实测测算）

⚠️ **重要更正**：原本设想"有显卡可跑 7B/14B"。实测显卡为 **RTX 5060 Laptop，总显存 8151 MiB、空闲 6967 MiB（≈6.8 GiB）**。按 Q4_K_M 量化实测测算：

| 模型 | Q4_K_M 权重 | KV@4K | KV@8K | **8K 上下文总计** | 6.8 GiB 内？ |
|---|---|---|---|---|---|
| Qwen2.5-Coder-**3B** | 1.74 G | 144 M | 288 M | **2.62 G** | ✅ 宽裕 |
| Qwen2.5-Coder-**7B** | 4.26 G | 224 M | 448 M | **5.29 G** | ✅ **可用（这就是上限）** |
| Qwen2.5-**14B** | 8.23 G | 768 M | 1536 M | **10.33 G** | ❌ 放不下 |
| Qwen3-**14B** | 8.29 G | 640 M | 1280 M | **10.14 G** | ❌ 放不下 |

（KV 按 Qwen2.5 全系 GQA 配置估算；上表按 Q4_K_M 约 0.56 GB/B 参数 + 0.6 G 缓冲计算，实际值随引擎与 batch 浮动。）

> **口径说明**：分项选型报告用更保守的参数给出 **7B ≈ 5.7 GB**（权重 4.7 G + KV 8K×2 槽 q8_0 0.22 G + CUDA/激活 0.8 G）。两处差异来自权重实测算与缓冲取值不同，**结论一致：7B 在 8K 上下文下可用，但余量只有 0.5 GB 左右**。建议以 `llama-bench` 在本机实测校准。
>
> **一个有用的洞察**：Qwen2.5 全系使用 GQA，KV cache 极小（7B 仅 **56 KiB/token**，8K 上下文仅 448 MiB）——**瓶颈是权重，不是上下文**。所以优化方向是压权重（量化），而不是砍上下文；同时开 `--cache-type-k q8_0` 还能把 KV 再砍一半。

### 由此确定的选型结论

1. **推理主力：Qwen2.5-Coder-7B-Instruct，GGUF Q4_K_M，上下文 ≤8K。** 这是 8 GiB 显存下的实际可用上限。推荐参数：

   ```
   --n-gpu-layers 99
   --ctx-size 8192
   --cache-type-k q8_0 --cache-type-v q8_0   # KV 448→224 MiB，关键技巧
   --parallel 2
   --jinja                                    # JSON Schema 约束输出
   ```

   显存实账：4.7（权重）+ 0.22（KV 8K×2 槽 q8）+ ~0.8（CUDA context/激活）≈ **5.7 GB**，余量仅约 0.5 GB。预期解码 **35–55 tok/s**，单题约 **6–7 秒**。

2. **14B / 16B-MoE 全部出局** —— Qwen2.5-Coder-14B Q4_K_M 约 9 GB、DeepSeek-Coder-V2-Lite 约 9.5–10 GB，均超出约 6.3 GB 的模型预算，只能 CPU offload，单题要 20–40 秒，教学场景不可接受。

3. **🔴 许可陷阱（比赛硬约束，务必核实）：Qwen2.5-Coder-3B 疑似不可商用。** 其镜像元数据为 `license: other` 而非 `apache-2.0`，且 "Qwen RESEARCH LICENSE AGREEMENT" 确为真实协议名。
   → **不要用 3B**。在 8 GB 约束下，唯一同时满足「Apache-2.0 明确可商用 ✅ + 装得下 ✅」的，是 **Qwen2.5-Coder-7B 与 1.5B**。
   → 已排除：Codestral-22B（MNPL，名称即含 Non-Production）、GLM-4-9B（智谱需单独商业授权）、DeepSeek-Coder-V2-Lite（装不下 + 自定义许可）。
   → ⚠️ 赛题要求"自主知识产权或合法授权"，**落地前请逐条打开官方 LICENSE 原文核对**。

4. **推理引擎：llama.cpp `llama-server`（Docker），明确排除 vLLM。** 理由是双重的：
   - vLLM 为高并发设计，8 GB 下额外开销大、易 OOM；你的场景是单机低并发
   - **系统 Python 是 3.14，而 PyTorch 在 3.14 上没有 CUDA/GPU 轮子**（只能装 CPU 版）→ vLLM / transformers / Unsloth / LLaMA-Factory **全部被连带阻断**
   - 而 `llama-server` 是**独立 C++ 二进制，完全不依赖 Python**，因此 Python 3.14 对推理链路零影响

5. **⭐ 环境三段式隔离（重要工程决策）**：

   | 用途 | 环境 | 说明 |
   |---|---|---|
   | ① 推理服务 | Docker + CUDA 12.8+，`ghcr.io/ggml-org/llama.cpp:server-cuda` | 彻底绕开 Python 3.14 |
   | ② FastAPI 胶水层 | **建议 Python 3.12 venv**（而非系统 3.14） | `pydantic-core`（Rust 扩展）在 3.14 上轮子可能滞后，装不上就降级 3.12，不要硬撑 |
   | ③ 微调（可选） | 独立 Docker 镜像 Python 3.11/3.12 + cu128 | **绝不要在系统 3.14 上做微调** |

6. **微调策略：分两阶段，现在不微调。**
   - **阶段一（现在）**：不微调。规则层 + 7B Q4 + few-shot + 强 Schema。此时还没有标注数据，且 sm_120 微调生态不成熟，容易卡在环境上浪费时间
   - **阶段二（积累 1000+ 条后）**：微调 **1.5B**（Apache-2.0，QLoRA 约 3–4 GB 舒适可行）专做"诊断 + 提示措辞"
   - **7B 的 QLoRA 在 8 GB 下约需 6.2–6.7 GB，很可能 OOM** → 若要微调 7B，**放云端/借卡做一次，导出 GGUF 回本地只做推理**
   - 注意定位：1.5B 微调版是 7B 的**降本替代**（延迟 6s→2s），**不是能力替代**。LoRA 的甜区是**格式/话术/领域术语**，不是泛化推理
   - **数据来源优先规则层合成**（在正确解上做 AST 层错误注入：off-by-one、缩进、类型、边界），零版权风险、可无限扩充，且 `error_helper.py` 的错误分类就是天然的标注 schema。**避免用闭源大模型蒸馏数据**——既有服务条款风险，也对"自主知识产权"主张不利

7. **🔴 最大单点风险：sm_120（Blackwell）生态不成熟。** 已有公开案例：llama.cpp 在 RTX 5060 上服务初始化**静默崩溃**；旧 PyTorch（cu124 及以下）报 `no kernel image is available`；Unsloth/bitsandbytes 4-bit 内核有兼容问题。
   → **第 1 天必须先做一件事验证全链路，不要先堆模型**：

   ```bash
   docker run --rm --gpus all ghcr.io/ggml-org/llama.cpp:server-cuda --list-devices
   ```

   若看不到 GPU，或起 1.5B 时崩溃，先换镜像/驱动版本——**这是整个项目的前置条件**。

8. **部署形态**：Docker 封装（Docker 已可用），把"校园内网一键部署、断网可用"做成真实交付能力，而非文档口号。这也是 §1.5① 政策合规的落地方式。

### 关键架构原则：**LLM 永远不做判题决策**

这一条比模型选型重要得多，且直接支撑"技术实现"得分：

| 层 | 职责 | 是否调模型 |
|---|---|---|
| **L0 确定性层** | `ast.parse()` 语法错误定位 · 公开+隐藏用例执行 · **AST 归一化指纹**（变量重命名 + 常量折叠 + 结构哈希）接受多解 · 规则匹配已知错因 | ❌ 零延迟零显存 |
| **L1 语义诊断** | 仅当 L0 未命中/无法归类时调用。输入 = 学生代码 + AST 摘要 + 用例 diff + 规则层候选错因；输出 = **约束解码 JSON**（错因枚举 + 证据行号 + 少儿话术 + L1–L3 提示 + confidence） | ✅ 唯一调模型处 |

**预计 60–80% 的提交在 L0 就得到判定**，模型调用量可降一个量级。

**防假阴性的不对称设计（教学产品最致命的错误是把对的判成错的）**：
> L0 判定"通过"时**直接通过，不送模型复核**；只有判定"不通过"或无法归类时才调模型，且**模型永远无权把"不通过"翻转为"通过"**，只能补充解释与提示。

**后置校验铁律**：约束解码只保证**语法合法**，不保证**语义正确**。必须叠加 Pydantic 值域校验 → **证据行号存在性校验**（行号不存在则整个输出作废）→ 枚举合法性校验 → 失败重试 ≤2 次 → 仍失败则**降级为模板化输出（不调模型）**。

> 业界依据："LLM-as-a-Judge Is Not an Oracle"；CodeHelp 的"LLM + 教学护栏（guardrails）"范式。

### 一个被低估的机会：中文友好输入层

有文献支持——非英语母语者学编程存在额外认知负荷；Python 的英文关键字、**英文报错信息**、打字速度，是从积木过渡到文本的明确障碍。而本地模型恰好能做"**中文报错解读 + 关键字中英对照 + 补全/填空式编码**"，这是低龄与农村校的真实需求，也是竞品普遍没做好的地方。

## 8. 必须先做的三件事（与创新无关，但不做会直接失分）

这三项不是"创新点"，而是**解除失格风险**的地基，应排在任何新功能之前：

1. **重做代码执行隔离**——不能再靠 AST 黑名单。改为**子进程 + 资源限制**（Windows Job Object / Linux rlimit）或**浏览器端 WASM（Pyodide）**执行。附带收益：这本身是个可讲的技术亮点——"不信任的学生代码永不落服务器"。
2. **修认证与合规**——JWT 密钥外置到环境变量、密码重置加验证码校验、所有业务接口注入 JWT 依赖、按用户隔离数据。面向未成年人的产品，这是合规底线。
3. **补方案完整性文档**——说明书、核心算法说明、测试报告、部署指南。**其中测试报告可以拿本次沙箱逃逸作为"发现问题 → 修复 → 回归验证"的素材**，这类"真实缺陷闭环"比通篇"测试通过"更有说服力。
