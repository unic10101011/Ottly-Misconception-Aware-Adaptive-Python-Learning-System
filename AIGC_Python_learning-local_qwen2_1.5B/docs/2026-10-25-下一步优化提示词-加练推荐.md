# 下一步优化提示词：补齐加练推荐数据并优化推荐流程

## 一、任务背景

项目当前已有：

- 45 道可以真实运行和判题的加练题；
- 学生主线题提交失败后，由程序判题并调用 AI 分析；
- AI 分析能够返回固定范围内的 `misconception_tag`；
- 学生改对主线题后，系统能够推荐一道真实加练题；
- 推荐结果会缓存，不会因为推荐失败影响通关记录。

目前的主要问题是：

1. 加练题有两种源文件结构，参与推荐的关键字段不统一；
2. 加练题没有明确的目标误区标签；
3. `practice.json` 中题目的难度目前在加载时统一写成 `1`；
4. 推荐主要依赖 AI 理解自由文本 `practice_focus`，缺少稳定的程序规则；
5. 推荐需要额外调用一次模型，模型超时或不可用时无法给出备用推荐。

题目数量不同不属于本次问题，不要求每一关的加练题数量相同。

## 二、本阶段目标

请在现有代码上完成：

```text
补齐加练题推荐数据
→ 使用固定误区标签匹配题目
→ 程序规则优先选择加练题
→ 多道题同样合适时再让 AI 辅助选择
→ AI 不可用时仍能返回规则推荐
```

本阶段不要重新搭建题库、重写判题器或增加新题。

## 三、开发要求

### 1. 先阅读和复用现有代码

请先检查：

- `backend/app/services/problem_catalog.py`
- `backend/app/services/practice_recommendation.py`
- `backend/app/services/error_analysis.py`
- `backend/app/services/personalized_history.py`
- `backend/app/api/coding.py`
- `backend/app/data/practice.json`
- `backend/app/data/practice-*.json`
- `backend/tests/test_practice_catalog.py`
- `backend/tests/test_practice_recommendation.py`
- `backend/tests/verify_practice_content.py`

尽量复用现有 `Lesson`、`PracticeSpec`、`misconception_tag`、候选题过滤、权限检查和推荐缓存逻辑，不要重复建立新的题库或推荐接口。

### 2. 补充统一的推荐字段

所有加练题加载为 `Lesson` 后都必须包含：

```json
{
  "difficulty": 1,
  "knowledge_ids": ["K08"],
  "target_misconception_tags": ["accumulation_error"],
  "source_url": "https://example.com/source"
}
```

字段要求：

- `difficulty` 只能是 `1`、`2`、`3`；
- `target_misconception_tags` 至少一个、最多两个；
- `source_url` 必须是实际参考来源，不能编造；
- 主线题允许没有目标误区标签；
- 加练题必须具有目标误区标签。

### 3. 使用现有固定误区标签

只允许使用：

```text
range_boundary
accumulation_error
condition_error
variable_error
syntax_error
other
```

每个标签必须根据题目真实考查内容和测试用例人工标注：

- 循环题不能全部默认标成 `range_boundary`；
- 只有能够检查累加器初始化、更新、重置或覆盖的题，才能标记 `accumulation_error`；
- 只有能够检查条件表达式、分支顺序或逻辑运算的题，才能标记 `condition_error`；
- `other` 只用于确实无法归入其他类别的通用练习。

### 4. 兼容现有两种题目文件

不要在本阶段把 `practice.json` 中36道题全部拆成独立文件。

需要：

- 给 `PracticeSpec` 增加 `difficulty` 和 `target_misconception_tags`；
- 加载 `practice.json` 时，把字段原样传入 `Lesson`；
- 给9个独立加练题文件补充相同的运行时字段；
- 两种源文件加载后必须得到一致的 `Lesson` 推荐字段。

### 5. 改成规则优先推荐

推荐候选题必须满足：

1. 是已发布的加练题；
2. 学生已经满足前置条件；
3. 学生尚未通过该题；
4. 与当前错误至少有一个相同 `knowledge_id`。

候选题优先级依次为：

```text
目标误区标签匹配
→ 知识点匹配
→ 难度接近
→ problem_id 稳定排序
```

第一版不开发复杂能力模型，可以暂时以难度 `1` 为默认目标难度。

### 6. 减少不必要的AI调用

- 存在唯一最佳候选题时，直接推荐，不调用 AI；
- 多道题在误区、知识点和难度上同样合适时，才允许 AI 辅助选择；
- AI 只能从候选 ID 中选择，不能生成新题；
- AI 只负责生成简短推荐理由，不能改变候选题过滤结果；
- AI 超时、模型不可用、JSON 错误或返回候选集外 ID 时，使用规则排序第一题；
- AI 失败不能使推荐接口返回无题，也不能影响已经保存的通关结果。

### 7. 只使用可信误区标签

只有同时满足以下条件时，才能使用 AI 分析中的 `misconception_tag`：

```text
analysis.status == ready
analysis.source == ai
analysis.content 存在
misconception_tag 属于固定标签集合
```

模型不可用、解析失败或没有分析时，不得把它记录为学生的 `other` 误区。此时只根据知识点、难度和稳定排序推荐。

### 8. 保持接口兼容

前端目前使用：

```json
{
  "status": "ready",
  "recommendation": {
    "problem_id": "practice-08-1-v1",
    "level_no": 8,
    "title": "连续编号总和",
    "reason": "这道题可以帮助你巩固累加过程。",
    "model": "rule"
  }
}
```

不要删除或改名现有返回字段。规则直接推荐时，`model` 可以使用明确值 `rule`；AI辅助选择时保留实际模型名称。

## 四、测试要求

修改前先补测试，至少覆盖：

1. 所有加练题都有合法难度、知识点、目标误区标签和来源；
2. 未知误区标签会导致题库校验失败；
3. `accumulation_error` 优先推荐累加类练习；
4. `range_boundary` 优先推荐循环边界练习；
5. `variable_error` 不会因为关卡相同优先推荐边界题；
6. 没有可信误区标签时仍能按知识点推荐；
7. 唯一最佳题不会调用 AI；
8. 多题并列时允许调用 AI；
9. AI 超时或返回非法结果时使用规则第一题；
10. 已通过、未发布或未解锁题目不进入候选集；
11. 重复读取同一次推荐不重复调用模型；
12. 加练题通过、失败或跳过均不改变主线解锁状态；
13. 45道题的参考解全部通过；
14. 每道题的典型错解至少失败一个测试。

建议执行：

```powershell
cd backend
python tests/verify_practice_content.py
python -m pytest tests/test_practice_catalog.py -q
python -m pytest tests/test_practice_recommendation.py -q
python -m pytest -q
```

前端接口未改变，也需要确认构建未受到影响：

```powershell
cd ../frontend
npm test -- --run
npm run build
```

## 五、手工验收流程

至少手工验证以下流程：

```text
学生提交错误代码
→ 程序判题失败
→ AI返回疑似误区
→ 学生修改后通过
→ 系统优先匹配同误区加练题
→ 学生进入并提交加练题
→ 主线解锁状态不受加练影响
```

然后关闭或移除 DeepSeek 配置，再验证：

```text
提交失败
→ 修改后通过
→ 系统仍然能够通过规则返回一道真实加练题
→ 通关记录和推荐缓存正常保存
```
