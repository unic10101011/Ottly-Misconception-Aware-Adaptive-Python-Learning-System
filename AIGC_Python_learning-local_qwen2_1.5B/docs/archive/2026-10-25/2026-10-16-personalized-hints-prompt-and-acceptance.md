# 个性化历史提示开发提示词与验收要求

## 一、当前基础

当前项目已经具备：

- 程序先判题、AI 不负责判断对错；
- 判题结果先返回，失败后再请求 AI 三级提示；
- 提交记录、错题记录、复习提交和提示查看级别持久化；
- 固定的 `misconception_tag` 疑似误区标签；
- 当前用户的疑似误区统计及前端概览；
- 十二关版本化题目、`knowledge_ids`、难度和提交快照；
- 模型超时、不可用和非法输出时的降级处理。

当前尚未实现“使用相关历史错误生成更有针对性的提示”。错题接口中的 `related_questions` 仍为空，仓库中也没有经过审核的独立加练题目录，因此本阶段只实现个性化历史提示，不实现同类题推荐。

## 二、开发提示词

请先阅读现有的提交、异步分析、学习记录、疑似误区统计、题目目录和前端三级提示代码，在现有结构上做最小修改。

本阶段目标是：学生当前提交失败时，后端自动选择该学生少量、相关、已经保存的历史错误摘要，交给 Qwen 作为辅助背景，使三级提示更贴合学生的学习经历。

当前题目的真实判题证据始终具有最高优先级。历史记录只能帮助调整讲解角度，不能改变程序判题结果，也不能证明学生本次一定犯了以前的错误。

### 1. 历史记录由后端选择

前端不得上传历史记录、用户 ID、误区标签或知识点。生成分析时，后端根据当前登录用户和当前提交，从数据库选择相关历史。

候选记录必须同时满足：

- 属于当前登录用户；
- 不是当前提交；
- 是以前的失败提交；
- `analysis.status` 为 `ready`；
- 存在合法的 `misconception_tag`；
- 与当前题目的 `knowledge_ids` 至少有一个交集。

选择规则：

1. 按提交时间从新到旧排列；
2. 最多选择 3 条；
3. 优先选择不同题目的记录，避免同一道题连续提交淹没其他经历；
4. 没有相关历史时使用空数组，保持现有普通提示流程；
5. 不使用 AI 再做一次历史检索或相关性判断。

旧提交没有 `knowledge_ids` 时，不猜测、不读取当前题库回填，也不加入本次个性化上下文。

### 2. 只发送必要的历史摘要

历史摘要只允许包含：

```json
{
  "problem_id": "range-sum-v1",
  "problem_title": "循环求和",
  "knowledge_ids": ["K06"],
  "error_type": "WRONG_ANSWER",
  "misconception_tag": "range_boundary",
  "suspected_cause": "循环范围可能没有包含最后一个数。",
  "later_passed": true,
  "hints_viewed_max": 2,
  "created_at": "2026-10-16T08:00:00Z"
}
```

不得发送：

- 历史学生代码全文；
- 历史测试输入、期望输出或实际输出；
- 隐藏测试内容；
- 其他用户信息；
- 登录令牌、邮箱、密码或账号资料；
- 全部提交历史。

### 3. 模型使用历史的规则

在现有提示词中加入以下约束：

- 当前题目、当前代码和当前公开判题证据是本次分析的唯一事实依据；
- 历史摘要只能帮助选择更容易理解的讲解方式；
- 不能因为历史中出现过某个误区，就直接认定本次仍是相同误区；
- 当前证据不足时继续使用 `other`，不能让历史记录替代证据；
- 历史中存在后来做对的记录时，应把它理解为学生已有改正经历，不能说学生“一直不会”；
- 只有至少两条相关历史记录支持同一模式，并且当前证据也支持时，才能使用“你以前也容易在这里混淆”一类措辞；
- 面向十几岁的初学者，一句话只讲一个重点，少用术语；使用术语时顺手解释；
- 三级提示仍按“思考方向 → 检查位置和知识点 → 具体修改或验证思路”逐步深入；
- 不提供完整正确代码，不泄露最终答案。

### 4. 返回个性化状态

在分析结果中增加可选的个性化元数据：

```json
{
  "personalization": {
    "used": true,
    "related_history_count": 2
  }
}
```

规则：

- 实际向模型提供了至少一条历史摘要时，`used=true`；
- 没有相关历史时，`used=false`、`related_history_count=0`；
- 固定语法提示未使用历史时为 `false`；
- 模型不可用或分析失败时不能声称使用了个性化提示；
- 不向前端返回历史提交 ID 或具体历史摘要。

前端只有在 `used=true` 时显示简短说明：

> 本次提示参考了你的相关练习记录。

不要在页面上直接贴出旧错因，也不要把“疑似误区”显示成确定结论。

### 5. 保存与重复请求

- 个性化分析仍保存在当前提交的 `analysis_json` 中；
- 保存 `personalization.used` 和 `related_history_count`，不保存发送给模型的完整历史摘要；
- 同一提交已有终态分析时直接返回已有结果，不能因为刷新页面再次调用模型；
- 以后新增提交不能自动改写旧分析；
- 正确提交继续跳过 AI，不读取历史记录；
- “运行代码”不读取历史记录、不生成分析。

### 6. 与现有功能的边界

必须继续复用：

```text
problem_id
problem_version
knowledge_ids
judge
analysis_json
misconception_tag
hints_viewed_max
```

不得修改程序判题结论，不得重新开发判题器。

本阶段不实现：

- AI 自动生成练习题；
- 同类题推荐；
- `related_questions` 填充；
- 学生能力分数或完整知识追踪模型；
- AST 规则引擎；
- 复杂误区知识库；
- 模型训练或微调；
- 跨用户比较。

## 三、建议修改位置

请先核对实际代码结构，再决定最终文件；预计涉及：

- `backend/app/services/error_analysis.py`：接收受控历史摘要，增加模型约束和个性化元数据；
- `backend/app/api/coding.py`：在分析接口中按当前用户选择相关历史；
- 新增一个职责单一的历史摘要选择函数或服务，避免把复杂查询堆进 API；
- `backend/tests/test_submission.py`：验证模型输入、当前证据优先和重复请求；
- `backend/tests/test_learning_history.py`：验证用户隔离、知识点筛选和后来做对；
- `frontend/src/components/SubmissionFeedback.jsx`：仅在实际使用历史时显示个性化说明；
- `frontend/tests/submission-flow.test.cjs`：验证显示条件和现有判题展示不受影响。

不要重构无关文件，不要覆盖当前工作区中的其他修改。

## 四、验收要求

### 1. 相关历史选择

- 当前用户有 4 条相关历史时，只选择最近且最相关的最多 3 条；
- 优先覆盖不同题目；
- `knowledge_ids` 没有交集的记录不进入上下文；
- 通过提交、分析失败记录和当前提交不进入上下文；
- 没有相关历史时返回空数组，不影响现有分析；
- 旧记录缺少知识点时不猜测、不回填。

### 2. 用户隔离与隐私

创建用户 A 和用户 B：

- A 生成提示时只能使用 A 的历史；
- B 的记录不得出现在 A 的模型请求或响应中；
- 模型请求不得包含历史代码全文、隐藏测试、账号资料和登录信息；
- 前端响应不得包含具体历史摘要或历史提交 ID。

### 3. 当前证据优先

准备历史标签为 `range_boundary`，但当前代码和判题证据明确属于变量未定义：

- 本次标签应依据当前证据生成 `variable_error`；
- AI 不得因为历史记录继续输出 `range_boundary`；
- 程序判题结果保持不变。

准备只有历史误区、当前公开证据无法确定具体原因的情况：

- 本次仍应使用 `other`；
- 不得用历史记录强行确定具体误区。

### 4. 后来做对的处理

历史摘要中某题已经后来做对时：

- `later_passed=true`；
- 提示不得说学生“一直不会”或“仍未掌握”；
- 原错误历史仍然保留；
- 后来的正确提交不能被删除或忽略。

### 5. 个性化状态

- 实际使用 2 条历史时返回 `used=true`、`related_history_count=2`；
- 没有历史、固定语法提示、正确提交和模型故障时不能显示个性化说明；
- 页面刷新或重新进入错题时，已经保存的个性化状态仍然存在；
- 同一提交重复请求分析时不再次调用模型。

### 6. 初学者可读性

至少人工检查三种个性化提示：

- 循环边界；
- 累加逻辑；
- 变量未定义。

提示需要满足：

- 十几岁的 Python 初学者能理解；
- 每句话只表达一个重点；
- 专业词语有简短解释；
- 三级内容逐步深入且不重复；
- 不输出完整正确代码；
- 不声称观察到不存在的运行过程；
- 不把历史误区写成本次已确定的事实。

### 7. 故障与回归

模拟 Ollama 未启动、超时、非法 JSON 和审核不通过：

- 判题结果及提交记录不受影响；
- 不产生虚假的个性化状态；
- 不重复调用模型；
- 前端保留真实判题证据并显示现有降级说明。

运行：

```powershell
cd backend
python -m pytest -q
```

```powershell
cd frontend
node --test tests/*.test.cjs
npm run build
```

## 五、最终验收标准

学生提交错误代码后，程序先给出确定性判题结果；AI 分析接口只从当前用户的历史失败中选择最多 3 条知识点相关摘要，并在当前真实证据支持的范围内调整讲解。历史记录不能改变判题、不能替代当前证据、不能泄露其他用户或隐藏测试信息。没有合适历史或模型故障时，系统继续使用现有普通提示或降级流程。

本阶段完成后，再由 A 部分提供经过审核的加练题目录，并单独设计“同类题推荐与跳过”功能。
