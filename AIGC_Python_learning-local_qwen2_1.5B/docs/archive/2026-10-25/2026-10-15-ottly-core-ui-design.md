# Ottly 核心学习界面优化设计

## 目标与范围

优化 React 网页的登录、关卡选择、答题和 AI 对话，以及这些页面共用的导航和窄屏布局。保留现有海獭插画、海蓝色识别和 API 行为。`AIGC_setting` 独立设置应用、错题与个人中心内部功能、后端均不在本次改动范围内。

## 视觉方向

采用“海岸学习工作台”：浅蓝页面背景、偏白内容面板、较深的蓝色主操作与少量暖沙色点缀。海獭继续担任向导，出现在登录欢迎区、关卡引导、答题求助入口和聊天消息里。装饰图像不遮挡文字或按钮；阴影、圆角和动效保持一致，降低持续动画对代码阅读的干扰。

## 页面与组件

- **共用布局**：桌面保留侧栏，但换成 Ottly 品牌区和可辨认的当前导航；窄屏改成易点击的紧凑导航。各页共享内容宽度与留白规则。退出登录仍执行原有令牌清理。
- **登录**：将表单与海獭欢迎区组成自适应布局。登录/注册切换、提示、校验和 API 调用继续沿用现有逻辑；增加便于操作的密码可见性控制和明确的加载状态。
- **关卡选择**：在地图前展示学习标题、当前可进入关卡和进度说明；地图仍由后端关卡状态生成。锁定关卡给出明确状态；海獭入口使用真正的按钮进入 AI 对话。地图在窄屏下不溢出。
- **答题**：桌面上题目说明与代码工作区更易对照，窄屏按“题目 → 编写 → 运行/提交 → 反馈”顺序排列。保留草稿、运行、提交、提示、回顾等既有数据流；突出运行与提交的区别，海獭求助入口可键盘访问。
- **AI 对话**：强化对话/历史切换、消息区和输入区的层级；对话为空时展示海獭引导和可点选的示例问题。示例问题仅填入输入框，由用户主动发送。保留现有会话、历史、分页和接口逻辑。

## 交互与异常

按钮、导航、表单有清晰的悬停、焦点、禁用和处理中状态。动效只用于进入和操作反馈，并遵循系统减少动态效果的设置。加载、请求失败与空状态继续显示可读文本，不把失败伪装成成功。键盘可以完成导航、进入关卡、向海獭求助和发送消息。

## 验收

在桌面宽度与约 375px 手机宽度检查四个核心页面：主要操作可见，文本不被插画遮挡，无页面级横向溢出。确认原有登录、关卡状态、代码提交与聊天请求路径不变；运行现有前端测试和生产构建，再做浏览器视觉检查。后端已有未提交改动不纳入本次变更。
